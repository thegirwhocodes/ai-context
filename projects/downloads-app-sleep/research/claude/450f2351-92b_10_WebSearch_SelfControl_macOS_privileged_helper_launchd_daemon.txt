## Overview

SMJobBless demonstrates how to embed a privileged helper tool in an application, how to securely install that tool, and how to associate the tool with the application that invokes it. SMJobBless uses the Service Management framework that was introduced in Mac OS X 10.6 Snow Leopard, and as of 10.6 this is the preferred method for managing privilege escalation on OS X.

## Installation Process

launchd runs the helper tool as a daemon with root privileges. The helper tool is copied from the Contents/Library/LaunchServices directory inside your app bundle to /Library/PrivilegedHelperTools/, and once installed, it is managed by launchd.

Installation of the Helper Tool is done with SMJobBless, which in turn requires authentication by the end user with AuthorizationCreate, and SMJobBless will ask launchd to "install" your Helper tool in /Library/PrivilegedHelperTools/. After installation, the end-user will not need to give permission again to start the Helper Tool.

## Requirements

Your app must be signed, the helper tool must be signed, the helper tool must be located in the Contents/Library/LaunchServices directory inside the app's bundle, and the helper tool must be an executable, not an app bundle.

The application's Info.plist has an additional key, SMPrivilegedExecutables, whose value is a dictionary where each key in this dictionary is the name of a privileged helper tool contained in the application, and each key maps to a code signing identity, specified as a set of code signing requirements.

## Security & Authorization

The Service Management framework uses code signatures to ensure that the helper tool is the one expected to be run by the main application. Communication must go through the designated client application that is explicitly authorized in the Privileged Helper Tool's Info.plist under SMAuthorizedClients.
