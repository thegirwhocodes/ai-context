# Sabi Voice-Tutor: Call→Lesson Flow & Subject Handling

## TL;DR for the PM

There are **two parallel implementations** and they differ critically on subject support:

| | Next.js app (`curriculum-app/`) | Python server (`sabi-server/`) — **production** |
|---|---|---|
| Subject support | **Numeracy ONLY.** Literacy exists in the RAG/curriculum-content layer but is never routed to in a call. | **Literacy AND numeracy**, with per-student `course` routing and automatic literacy/numeracy alternation. |
| Routing key | Hardcoded `subject: 'numeracy'` everywhere | `learning_state.course ∈ {"numeracy","literacy"}` read live each turn |
| Sequencing | Flat module 0–7, advanced by post-call LLM analysis | Fixed module→week→lesson sequence (96 numeracy lessons, 80 literacy lessons), advance-only-after-mastery |

The memory notes (Sabi pipeline = Whisper + Haiku + Chatterbox on Hetzner GPU, Asterisk flash-callback) point at the **Python server** as the real phone pipeline. **That server already has the literacy/numeracy split fully built.** The Next.js routes are the older/serverless telephony path and are numeracy-only.

## 1. THE CALL→LESSON FLOW (end to end)

### A. Python production server (`sabi-server/`) — the flash-callback pipeline

Entry is `main.py` (`uvicorn main:app`). On startup (`lifespan`, `main.py:106+`) it loads `SpeechToText`, `TextToSpeech`, `SabiLLM`, `StudentMemory`, and starts **two** telephony servers:
- `start_agi_server` → `voice_asterisk.py` (Asterisk **FastAGI**, SIP flash-callback)
- `start_audiosocket_server` → `voice_realtime.py` (Asterisk **AudioSocket** realtime streaming)
(`main.py:48-52` imports; both started in lifespan.)

The per-turn lesson loop is identical in shape in both. Using `voice_asterisk.py` as the canonical trace:

1. **Identify student** by caller phone → `memory` student row.
2. **Load lesson state**: `effective_state = await memory.get_effective_learning_state(student)` (`voice_asterisk.py:365`, `voice_realtime.py:885`). This returns the saved `learning_state` JSON or infers it from the last 20 sessions (`memory.py:634-651`). `module = int(effective_state.get("current_module") ...)` (`:368`).
3. **Opening turn** is deterministic (returning callers are not re-asked their name): `build_opening_turn(student, state)` (`diagnostic_flow.py:373`) — and **it branches on course at line 389-390**: `if course == "literacy": return _build_literacy_opening_turn(...)`.
4. **Each child turn**: STT → update state via `analyze_session(...)` (`voice_asterisk.py:457-461`) which re-reads `current_module`/course → then:
   ```python
   response = await llm.generate(
       messages=llm_messages, student_id=..., current_module=module,
       memory=memory,
       course=str(effective_state.get("course") or "numeracy"),   # voice_asterisk.py:487, :514
       learning_state=effective_state, ...)
   ```
   `voice_realtime.py:1155` and `:1183` do the same. **This `course=` argument is the live literacy-vs-numeracy switch.**
5. **Prompt assembly** in `llm.py` `_build_system_prompt` (`llm.py:166-201`):
   - `SABI_CORE_PROMPT + SABI_SAFETY_PREAMBLE`
   - `_get_course_context(current_module, course)` → **`if course=="literacy": _get_literacy_context()` else `_get_rag_context(module)`** (`llm.py:374-377`)
   - `build_curriculum_path_prompt(learning_state, current_module, course)` (`llm.py:186`) — pins the exact lesson; **literacy-branched** (`curriculum_path.py:402`)
   - `build_instructional_route_prompt(messages, current_module, course)` (`llm.py:198`) — **literacy-branched** (`diagnostic_flow.py:460`)
6. **TTS** (Chatterbox `naomi` voice) → stream audio back; loop.
7. **Post-call** (`memory.py` analyze/persist): `advance_learning_state_after_mastery` (`memory.py:199`), then `route_next_course_after_session` (`memory.py:221`) decides the **next call's** course.

## 2. SUBJECT HANDLING — is there a literacy/numeracy notion today?

**Yes in the Python server; effectively no in the Next.js app.**

### Next.js app = numeracy only
- The RAG layer *can* express subject — `searchCurriculum(query, {subject})` and the `RetrievedChunk.subject` field accept `'literacy'` (`lib/rag/retrieval.ts:56`, `lib/rag/chunk.ts:13`). The chunker even produces literacy chunks: `if (subjectId === 'foundational-literacy') return 'literacy'` (`chunk.ts:79`), `literacy-${unitOrder}` (`chunk.ts:69`).
- **But the only consumer at call time hardcodes numeracy.** `getSabiCurriculumContext()` always queries `subject: 'numeracy'` (`retrieval.ts:126` and `:131`), maps modules to `sabi-counting/addition/.../word-problems` only (`retrieval.ts:105-113`), and `generateSabiModuleChunks()` tags every module `subject: 'numeracy'` (`chunk.ts:251`).
- The seeded learning-state is `course: "numeracy"` in three places: `lib/voice/sabi-shared.ts:548`, `app/api/sabi/student/route.ts:142`, and SQL `supabase-sabi-learning-state.sql:72`. Nothing in `curriculum-app/lib` or `app` ever sets course to literacy.
- Literacy content/standards DO exist as static assets but are **web-curriculum only**, not wired to voice: `lib/foundational-literacy.ts` (`Subject id:'foundational-literacy'`), `lib/standards/foundational-literacy-crosswalk.ts`, `lib/standards/assessment-blueprints.ts:180` (`literacyDiagnosticBlueprint`), and `app/subjects/[subject]` pages.

### Python server = both subjects, fully routed
The pivot variable is **`course`** (values `"numeracy"` | `"literacy"`, default `"numeracy"`). It is threaded through every layer:
- `llm.py:172,258,348` — `course` param; `:375 if course=="literacy"` → literacy RAG context; `:532 "## CURRENT COURSE: FOUNDATIONAL LITERACY"`.
- `curriculum_path.py:402 if course=="literacy"` → literacy curriculum-path prompt; `:530 "course":"literacy"`; `:541` literacy advance.
- `diagnostic_flow.py:381,389,458,460` — literacy opening turn + literacy diagnostic route.
- `learning_state.py:289 "course":"numeracy"` default; `:354,359,381` course-rotation select; `:531,642` literacy session analysis dispatch.
- `voice_realtime.py:277 state.get("course")=="literacy"`, `:1155,:1183`; `voice_asterisk.py:487,:514`; `memory.py:200,215,226,547`; `call_admin.py:493`; `curriculum_review.py:29,74`; `admin_review.py:807` (`current.course || "numeracy"` UI pill).

Notably the **STT layer is subject-aware too**: `stt.py` has a `literacy` mode with a dedicated Intron Sahara ASR provider (`SABI_LITERACY_STT_PROVIDER`, `stt.py:110,173-174`), a `LITERACY_ENGLISH_PROMPT` (`stt.py:42`), longer silence padding (`stt.py:300-301`), and a `local_literacy_salvage` path for short single-word answers (`stt.py:261-266`). `voice_realtime.py` picks STT mode via `_is_literacy_state(state)` (`:263-287`) and relaxes the confidence gate for literacy answers (`:1037-1089`).

**Verdict:** Today, a live phone call routed through the Python server delivers **both** numeracy and literacy depending on `learning_state.course`; the Next.js webhooks deliver **numeracy only**.

## 4. CURRICULUM STRUCTURE — where lesson content comes from

Content is assembled **at call time into the system prompt** (RAG-with-fallback), not read from per-lesson files during the call. There are three content sources:

**(a) Next.js `lib/voice/sabi-shared.ts` — hardcoded numeracy modules (the fallback, and what actually runs).**
- `MODULE_CURRICULUM: Record<number,string>` (`sabi-shared.ts:210-284`) — full teaching text for modules 0–6, **all numeracy** (DIAGNOSTIC, COUNTING, ADDITION, SUBTRACTION, MULTIPLICATION, DIVISION, WORD PROBLEMS). No literacy module exists here.
- Assembly in `callSabi`/`callSabiVoiceFast`: tries `getSabiCurriculumContext(currentModule)` (RAG, numeracy-filtered); on any failure or empty → `getModuleCurriculum(currentModule)` (the hardcoded text). Final prompt = `SABI_CORE_PROMPT + SABI_SAFETY_PREAMBLE + curriculumContext + VOICE_SYSTEM_ADDENDUM + memoryContext + numericGradingHint` (`sabi-shared.ts:636-642, 703-709`).
- `SABI_SYSTEM_PROMPT` (used by the ElevenLabs route) concatenates **all numeracy modules** (`sabi-shared.ts:296-300`).

**(b) Python server — deterministic lesson catalogs in `curriculum_path.py` (this is where literacy/numeracy are genuinely separated).**
- Numeracy: `MODULE_NAMES` (0–7), `MODULE_SKILLS`, `MODULE_START` (module→start week/global/week-count), `LESSON_TITLES` (**96 numbered lessons**, `curriculum_path.py:43-140`), `MODULE_PRINCIPLES`, `FALLBACK_MODULE_PROMPTS`.
- Literacy: `LITERACY_MODULE_NAMES` (1–6: Phonemic Awareness, Oral Vocabulary, Listening Comprehension, Oral English/Grammar, Advanced Phonemic Awareness, Print Bridge — `:169`), `LITERACY_MODULE_START` (with `phase` + `suffix`), `LITERACY_MODULE_SKILLS`, `LITERACY_LESSON_TITLES` (**~80 lessons across modules 1–5, by phase**, `:195-286`), `LITERACY_MODULE_PRINCIPLES`.
- At call time, `build_curriculum_path_prompt(state, module, course)` (`:395`) resolves the **exact** lesson: `resolve_numeracy_lesson` (`:297`) or `resolve_literacy_lesson` (`:347`), computing the concrete week/lesson/global-or-script-lesson and emitting a "CURRENT NUMERACY/LITERACY CURRICULUM PATH — HACKATHON LESSON DISCIPLINE" block (`:406-456`) that pins Sabi to one lesson for the whole call.
- RAG context: `llm.py` `_get_rag_context(module)` (numeracy, pgvector) vs `_get_literacy_context()` (`llm.py:529` — a static literacy guidance block, not a vector store yet).

**(c) Next.js static curriculum (web app only, not in the voice loop):** `lib/foundational-numeracy.ts` (216KB), `lib/foundational-literacy.ts` (204KB), `lib/cambridge-grade4-curriculum.ts`. These are the source the RAG chunker (`lib/rag/chunk.ts`) embeds, and they include literacy — but again, only numeracy is ever retrieved at call time.

So at call time a lesson's content = **core personality prompt + (RAG-retrieved or hardcoded) module text + deterministic "current lesson" pin + student memory**. Literacy vs numeracy content is separated **only in `sabi-server/curriculum_path.py`** (and the static `lib/*.ts` source); the live Next.js voice path assembles numeracy only.

## 5. EXISTING ROUTING / SEQUENCING — does anything decide which subject/lesson a call gets?

### Within-subject sequencing — YES, in both, but differently
- **Next.js:** module advance is decided **after** the call by an LLM analysis pass. `at/events/route.ts:159-213` asks Claude-Haiku for `should_advance`/`recommended_module`, then `nextModule = should_advance ? min(current+1,7) : recommended_module` (`:247-249`) and writes it back. There is no week/lesson concept and no subject choice — it's a flat 0→7 numeracy ladder.
- **Python:** strict module→week→lesson sequence, **advance-only-after-mastery**: `advance_numeracy_state_after_mastery` / `advance_literacy_state_after_mastery` (`curriculum_path.py:459, 497`) step to the next lesson record; in-call routing never jumps modules (`build_curriculum_path_prompt` rule: "Do not jump to the next module during the call").

### Subject (literacy↔numeracy) routing — YES, but ONLY in the Python server
`route_next_course_after_session(state, user_turns, has_learning_evidence)` (`learning_state.py:336-402`), called post-call from `memory.py:221`:
- If current course is `numeracy` and the numeracy diagnostic is done (`current_module>0`) → **switch next call to `literacy`** (`:359-379`): sets `course:"literacy"`, seeds the literacy diagnostic if not done, writes `course_rotation.next_course="literacy"`.
- If current course is `literacy` and literacy diagnostic done → **switch back to `numeracy`** (`:381-399`).
- Guarded: only switches after the child actually spoke (`user_turns>0 and has_learning_evidence`), and **never mid-call** (the comment at `:343-345`: "Pilot docs call for alternating literacy/numeracy… never switches the active lesson mid-call").

### "If a child calls twice in a day, does anything differ?"
- **Python server:** Yes. Call 1 finishes → `route_next_course_after_session` may flip `course` and `advance_*_after_mastery` bumps the lesson pointer; the saved `learning_state` is reloaded at the top of call 2 (`get_effective_learning_state`), so call 2 starts at the next lesson and possibly the alternate subject. The deterministic opening turn even greets with a recall warm-up for that subject (`diagnostic_flow.py:406-416` numeracy, `:445-455` literacy).
- **Next.js webhooks:** Differs only in numeracy module/skills (post-call analysis advanced the module); **subject never changes** (always numeracy). Within a single call, auto-wrap triggers at 12 user turns or on `WRAP_UP_PATTERNS` (`respond/route.ts:85-86, 18-29`).
