## 🔑 ROOT CAUSE of "greeting plays then silence" — AT `<Record>` casing bug (FIXED Jun 8, session 416308b0)
Real calls reached AT and the greeting played, but Sabi never replied — `/at/recording` never fired. **Root cause: AT's `<Record>` callback attribute is `callBackUrl` (capital B AND U), but our code used lowercase `callbackUrl`.** AT silently ignores the wrong-cased attr → treats Record as TERMINAL (records till hangup, no mid-call POST) → silence. Confirmed against AT's official PHP SDK (`' callBackUrl="'.$callBackUrl.'"'`). **Fix:** restored `callBackUrl` on both Record builders in `curriculum-app/lib/voice/at-xml.ts` (deployed + verified live) and `sabi-server/voice.py` (committed, not yet deployed to Hetzner). Also kept a safety net: `/at/incoming` detects a `recordingUrl` field and forwards to `/at/recording` (covers the case where AT posts the recording back to the main voiceUrl). Verified end-to-end via webhook replay: BOTH paths return Sabi audio and the response Record carries callBackUrl so the loop self-sustains. ⚠️ DO NOT remove `callBackUrl` again — a prior Claude removed it thinking AT didn't honor it (its test was invalidated by deploy/log timing). Final confirmation still pending a real Nigerian dial (Naomi tests via Yolla; her US Visible line can't dial +234). Latency ~5-6s/turn (AT path uses slow callSabi/Claude Haiku — port callSabiVoiceFast/Cerebras to speed up). Sentry was wired into curriculum-app (DSN set) by the prior Claude for visibility.
