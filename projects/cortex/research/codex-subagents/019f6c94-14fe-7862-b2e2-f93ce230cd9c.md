# Codex subagent report: Beauvoir

## Recommendation

Ship V1 as a manually configured, foreground macOS CLI. Do not modify Tauri for the V1 acceptance gate.

The smallest correct implementation is one production composition root that instantiates `LocalBridgeEngine` with an iMessage adapter, durable stores, uploader, and polling runner. Reuse the exporter’s extraction logic, but remove its independent checkpoint/upload path so there is only one durability and authentication implementation.

## Exact implementation

### Local bridge

Add:

- `local-bridge/src/imessage-scanner.ts`
  - Extract the SQLite snapshot/query/mapping code from `export-imessage.mjs`.
  - Export `probeImessageDatabase()` and `scanImessage()`.
  - Use `/usr/bin/sqlite3`, subprocess timeout/abort, a 100-item maximum, 5 MB encoded bound, 50-row edit-rescan window, and one-row lookahead for truthful `hasMore`.
  - Return bounded failures for poison rows so one oversized/corrupt message cannot permanently block the cursor.
  - Never read attachment bytes.

- `local-bridge/src/imessage-adapter.ts`
  - Implement `IMessageAdapter<ImessageLocalItem, {rowId:number}>`.
  - `checkPermission()` performs only a schema/open probe through `probeSourcePermission`.
  - `scan()` converts scanner records into upsert mutations with semantic hashes and always emits zero deletions.
  - Validate `consent.scope === account:${accountId}` and the configured device-row UUID.

- `local-bridge/src/runtime.ts`
  - Export `createIMessageBridgeRuntime(config)`.
  - This must visibly instantiate:

```ts
new LocalBridgeEngine({
  adapter: new MacIMessageAdapter(...),
  protocol: createLocalSourceV1Protocol(),
  consents: new ConsentRegistry(...),
  states: new JsonSourceStateStore(...),
  uploader: new AuthenticatedUploader(
    new MacDeviceCredentialResolver(),
    { audit }
  ),
  audit: new ContentFreeAuditLog(...),
});
```

- `local-bridge/src/cli.ts`
  - Commands: `identity`, `configure`, `probe`, `once`, `run`, `status`, `pause`, `resume`, `revoke`.
  - Store data under `~/Library/Application Support/Cortex/local-bridge/`.
  - `configure --token-stdin` should write an owner-only credential file or create a Keychain reference; never accept the token directly in argv.
  - `once` acquires a per-source lock, awaits `engine.run()`, prints only counts/health, and exits.
  - `run` performs an immediate run, then polls every 30 seconds using `DebouncedSourceRunner`.
  - Handle `SIGINT`/`SIGTERM`, stop timers, await the active run, and release the lock. If killed during upload, the already-persisted pending body remains replayable.

- `local-bridge/src/process-lock.ts`
  - Exclusive per-source lock with PID ownership and conservative stale-lock recovery.

## V1 acceptance boundary

V1 is accepted when a user can:

1. Run `identity` and register the resulting `lbd_…` device plus `account:ima_…` source while signed in.
2. Configure the returned source/device UUIDs, endpoint, and one-time bearer through token stdin/Keychain.
3. Grant Full Disk Access to the terminal process.
4. Run `probe` without reading or displaying message content.
5. Run `once`, receive an exact committed acknowledgement, and observe durable cursor/sequence with a cleared outbox.
6. Run `once` again and prove idempotency.
7. Prove with fixtures that an interrupted upload replays the exact pending body after restart.

A foreground `run` polling mode may ship and be tested, but V1 must not be described as always-on.

Always-on packaging is a separate release: emit a standalone signed sidecar, add it to `tauri.conf.json` `externalBin`, supervise it from a new `src-tauri/src/local_bridge.rs`, add single-instance handling, explicit launch-at-login controls, tray status/pause/resume, nested-helper signing/notarization, and verify Full Disk Access against the final installed signed app. The current Tauri shell does none of that.
