## 1. What "combobulating" actually is — definitive answer

**"Combobulating" is NOT an Antigravity string. It is a Claude Code spinner verb.** The fact that Naomi is seeing it in Antigravity's chat panel is the smoking gun: **Antigravity is rendering the spinner from the underlying model/tool runner, which in her case is Claude — so the text she's reading comes from Anthropic's Claude Code-style status vocabulary, not from Google's UI.**

Hard evidence:

- **`levindixon/tengu_spinner_words` GitHub repo** lists Claude Code's 90 internal spinner words. **"Combobulating" appears in that list** (alphabetically between "Coalescing" and "Computing"). Other verbs in the same set: "Clauding", "Cogitating", "Discombobulating", "Flibbertigibbeting", "Honking", "Noodling", "Recombobulating", "Reticulating", "Schlepping", "Spelunking", "Wibbling", "Wizarding". The repo notes Claude Code's internal codename is **"Tengu"** (天狗, Japanese for the supernatural mountain-warrior spirit) — visible in Statsig config keys like `tengu_spinner_words`. [tengu_spinner_words repo](https://github.com/levindixon/tengu_spinner_words)

**What phase it maps to:** It is purely a cosmetic loading/streaming indicator. It does **not** correspond to a specific phase like "tool selection" or "planning." ## 2. Why Claude is specifically slow inside Antigravity — the API routing

**Antigravity does NOT call Anthropic directly when you pick a Claude model.** It tunnels Claude through Google's own internal Cloud Code companion endpoint. Verified routing details from multiple reverse-engineering projects:

- Antigravity expects requests at **`cloudcode-pa.googleapis.com/v1internal:generateContent`** with a **Google OAuth bearer token** — not an Anthropic API key. [badrisnarayanan/antigravity-claude-proxy](https://github.com/badrisnarayanan/antigravity-claude-proxy)
- Fallback / daily ladder: `https://daily-cloudcode-pa.sandbox.googleapis.com` → `https://daily-cloudcode-pa.googleapis.com` → `https://cloudcode-pa.googleapis.com` (from the CLIProxyAPI server logs in the rate-limit thread). [CLIProxyAPI issue #1015](https://github.com/router-for-me/CLIProxyAPI/issues/1015)
- **Model name normalization**: Anthropic public IDs (`claude-sonnet-4-5-20250929`) ≠ Antigravity internal IDs (`claude-sonnet-4-6`, `gemini-claude-opus-4-5-thinking`). The proxy renames in both directions. The Antigravity API "doesn't return a friendly error for an unknown model — it 404s with no JSON body." [DEV: I Pointed Claude Code at Antigravity](https://dev.to/codekingai/i-pointed-claude-code-at-googles-antigravity-heres-the-5-minute-oauth-setup-45bp)
- Each request is transformed from Anthropic Messages format → Google `generateContent` shape → response is then re-streamed back as Anthropic SSE. **Two serialization passes per request, every request.**
- User-Agent that Antigravity sends: `antigravity/1.104.0 darwin/arm64` (so macOS users like Naomi do get an arm64 build).
- **Practical impact** documented in `lbjlaq/Antigravity-Manager` issue #678 by user `senja24` (Jan 15 2026, macOS, Claude Code CLI v2.1.7): *"Latency should be roughly comparable to Antigravity app for the same model/prompt (or at least not 5-10x slower)"* — but is. Even with the fix, *"every request need to wait until almost a minutes for each account before start to work."* [Antigravity-Manager#678](https://github.com/lbjlaq/Antigravity-Manager/issues/678)
- Companion user `tjengbudi` chimed in: *"It will much better if it is not banned"* — confirming that Claude routing through Antigravity's relay is fragile and intermittently rate-limited.
- Chinese user `buer0301-art` (Jan 15 2026): *"同样，今天开始慢的。昨天还好好的"* ("Same, started being slow today. Was fine yesterday.")

**Bottom line:** Naomi's prompts are NOT going Claude Code → Anthropic. They are going **Antigravity UI → Antigravity backend → cloudcode-pa.googleapis.com (Google's internal Cloud Code companion) → Google's internal Claude proxy → Anthropic.** Every extra hop adds time, and Google's Claude offering on this endpoint is widely reported to throttle aggressively even when quota APIs show 100% remaining.

- Quit Antigravity entirely, delete `~/Library/Application Support/Antigravity` AND `~/.antigravity_cockpit`, decide which bundle to keep (Google's officially-supported one is `com.google.antigravity-ide` for the IDE; `com.google.antigravity` is the 2.0 Hub), and uninstall the other.
- Update to **2.0.10** (Google support's recommended threshold).
- Create `.antigravityignore` with `node_modules/`, `dist/`, `build/`, `.next/`, `.git/`.
- Cap active MCP servers to **≤ 25 tools** total.
- When the spinner runs > 30s, hit **Cmd+L** for a fresh chat (budget reset).
- If still slow, the underlying issue is the Google relay — there is no client-side fix for that; the workaround documented by every proxy project is to use Claude via `api.anthropic.com` directly (which means leaving Antigravity for that model).
