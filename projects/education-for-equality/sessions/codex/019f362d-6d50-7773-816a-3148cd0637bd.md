## Codex · 2026-07-06T06:50:06.216Z · final_answer

Yes. Africa’s Talking has inbound SMS.

The catch: it’s mainly through **Two Way SMS / short codes**, not necessarily your current Sabi voice number. Their docs say you receive inbound messages by setting an **Incoming Messages callback URL** in the dashboard: `SMS → SMS Callback URLs → Incoming Messages` [official docs](https://developers.africastalking.com/docs/sms/notifications).

For Nigeria, their Two Way SMS page shows a **shared short code keyword** option, with:
- Monthly maintenance: **NGN 10,000 + 7.5% VAT**
- Incoming SMS: **NGN 6.00**
- Outgoing SMS: **NGN 5.40**  
Source: [Africa’s Talking Two Way SMS](https://africastalking.com/sms/twowaysms)

For Sabi, this is useful for things like:
- parent/caregiver opt-in: `YES SABI`
- consent confirmation
- “call me” triggers
- support / stop / help commands
- follow-up SMS after calls

So: **yes, AT can receive SMS into your backend via webhook, but we’d likely need a short code or shared keyword for Sabi.**

Yes. Do it in two passes: first prove **our backend works**, then prove **Africa’s Talking can reach it live**.

**1. Check Supabase**
In Supabase SQL Editor, run:

```sql
select table_name
from information_schema.tables
where table_name in ('sabi_sms_log', 'sabi_prepilot_participants');

select column_name
from information_schema.columns
where table_name = 'sabi_sms_log'
order by ordinal_position;
```

You want `sabi_sms_log` and `sabi_prepilot_participants`. If missing, run:

- [supabase-sabi-telephony.sql](/Users/naomiivie/Education%20for%20Equality/curriculum-app/supabase-sabi-telephony.sql)
- [supabase-sabi-prepilot.sql](/Users/naomiivie/Education%20for%20Equality/curriculum-app/supabase-sabi-prepilot.sql)

**2. Set local env**
In `curriculum-app/.env.local`, add:

```bash
AT_API_KEY=...
AT_USERNAME=sandbox
AT_SENDER_ID=
NEXT_PUBLIC_SABI_LINE="+234 201 700 1459"
SABI_SMS_WEBHOOK_SECRET=[REDACTED:sabi-sms-webhook-secret]
```

Generate the secret with:

```bash
openssl rand -hex 32
```

Do not paste the real value into chat.

**3. Run local backend test**
From `curriculum-app`:

```bash

```

Then test an Africa’s Talking-style inbound SMS:

```bash
curl -i -X POST "http://localhost:3000/api/sabi/sms/incoming?key=$SABI_SMS_WEBHOOK_SECRET" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "from=+2348012345678" \
  --data-urlencode "to=12345" \
  --data-urlencode "text=HELP" \
  --data-urlencode "id=1" \
  --data-urlencode "linkId=test"
```

Good result: HTTP `200` with `{"ok":true}`.

Then confirm it logged:

```sql
select phone_number, direction, message, sms_type, channel, created_at
from sabi_sms_log
order by created_at desc
limit 10;
```

You should see `direction = inbound`, `sms_type = help`, `channel = at`.

**4. Test the helper UI**
Open:

```text
http://localhost:3000/sabi/parents
```

Good result: caregiver roster loads, provider banner appears, templates preview, and sending is blocked until the confirm modal.

If the roster is empty, add one test participant in Supabase first or use the prepilot flow.

**5. Set production env**
In Vercel production, set:

```bash
AT_API_KEY
AT_USERNAME
AT_SENDER_ID
NEXT_PUBLIC_SABI_LINE
SABI_SMS_WEBHOOK_SECRET
```

Important: `AT_USERNAME=sandbox` means test mode. For real phones, use the production Africa’s Talking username/API key.

**6. Configure Africa’s Talking**
In Africa’s Talking dashboard:

```text
SMS -> SMS Callback URLs -> Incoming Messages
```

Paste:

```text
https://eduforequality.org/api/sabi/sms/incoming?key=<SABI_SMS_WEBHOOK_SECRET>
```

For real inbound caregiver replies, you likely need Two Way SMS with a short code/shared keyword. Use that short code as `AT_SENDER_ID` if you want replies to route back correctly.

**7. Live smoke test**
Send one caregiver SMS from `/sabi/parents` to your own phone first.

Then reply:

```text
HELP
```

Expected: Sabi replies with help text, and `sabi_sms_log` shows inbound `help`.

Then reply:

```text
hello
```

Expected: caregiver status becomes “They replied.”

Then reply:

```text

```

Expected: Sabi sends pause confirmation and logs `opt_out`.

One caveat: STOP is logged and acknowledged, but the dashboard is still concierge/manual. So after STOP, do not manually send that number again.
