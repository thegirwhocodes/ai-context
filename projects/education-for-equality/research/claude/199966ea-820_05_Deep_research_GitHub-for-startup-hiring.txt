## 1. Top universal patterns (verified across all 13 profiles fetched)

### 1a. The profile README is OPTIONAL — and absence reads as confidence
- leerob (Cursor, 15.9k followers) — no profile README
- levelsio (legendary solo founder, 5.2k followers) — no profile README
- torvalds (306k followers) — no profile README
- jamiebuilds (Signal eng, 8.9k followers) — effectively no profile README
- rauchg (Vercel CEO, 16.8k followers) — the README is a *joke* (npm install rauchg)

Only profiles that *teach* or *evangelize* (swyx, jdhao, sindresorhus) carry a substantive profile README. **The "Hi 👋 I'm Naomi" template signals job-seeker, not founder.** ([Codeboards 2026 guide](https://codeboards.io/blog/github-profile-readme-guide), [Hacker News thread](https://news.ycombinator.com/item?id=16224401))

### 1b. Pinned repos are doing 90% of the work
Every single high-status profile I fetched used the 6 pinned repos as the primary story device. They are ordered with the strongest project in position 1 — boot.dev's piece confirms this explicitly: *"put those in order, with your best works at the top. Consider that most people are going to only look at your first one or two repositories."* ([boot.dev guide](https://www.boot.dev/blog/jobs/build-github-profile/))

### 1c. The bio under the avatar is short, present-tense, and declarative
Verified bios:
- `"Teaching developers about AI"` (leerob)
- `"Full-Time Open-Sourcerer. Focused on Swift & JavaScript. Makes macOS apps, CLI tools, npm packages."` (sindresorhus)
- `"Chief Shitposting Officer @ Levels Synergies & Co"` (levelsio)
- `"My heart is open source 💕 Formerly @amzn, @microsoft"` (transitive-bullshit)
- `"Swimming 🏊 in the sea of code~~"` (jdhao — most junior-looking of the set)

Pattern: **6–15 words, no list of skills, no "open to opportunities," no graduation year, no location-or-stack stuffing.** Founder bios are verbs (*Building, Teaching, Shipping, Makes*); job-seeker bios are nouns ("Full-stack developer | React | Node.js | Open to opportunities").

### 1d. `hireable: false/null` — the "Available for hire" flag is OFF for every founder I checked
Confirmed via `gh api`: leerob, transitive-bullshit, levelsio all have `"hireable": null`. The flag exists ([GitHub docs](https://docs.github.com/en/account-and-profile/how-tos/account-settings/set-your-hiring-status)) but founders never turn it on — it inverts the power dynamic. GitHub Jobs is also deprecated, so the flag is mostly vestigial signal anyway. **Recommendation: Naomi should NOT toggle "Available for hire" on.**

### 1e. Recent activity > everything else recruiters scan
Fonzi.ai's 2026 recruiter-survey article: *"about 80 percent of final hiring decisions still hinge on system design interviews and references"* but the contribution graph is the very first thing recruiters check for "is this person actually shipping right now." ([Fonzi.ai](https://fonzi.ai/blog/do-recruiters-check-github)). Long gaps followed by sudden activity reads as "padding before a job hunt" — verified across [Medium 7 mistakes](https://medium.com/@kantmusk/7-github-profile-mistakes-that-cost-you-job-offers-e6b37ea92238) and the [Codeboards guide](https://codeboards.io/blog/github-profile-readme-guide).

### 1f. Stars and followers do matter — but mainly as social proof on individual pinned repos
[Kula.ai 2026 guide](https://www.kula.ai/blog/github-beginners-guide-source-candidates) and the Codeboards article: a pinned repo with 500+ stars functions as a third-party endorsement. Below ~50 stars, the star count is invisible noise. Followers >1k is a notable threshold; below that, the number is decorative. Naomi shouldn't *hide* low-star repos — she should make the *pinned set* signal high quality and let the rest sit on page 2.

### 1g. The 30-second rule is real and stricter for AI-native hiring
Multiple sources converge: recruiters spend 30 seconds on initial scan ([gittohire.com 2026](https://gittohire.com/blog/optimize-github-profile-job-hunting-2026), [boot.dev](https://www.boot.dev/blog/jobs/build-github-profile/)). For AI startups specifically, the bar is "does this person ship AI products end-to-end" — meaning the pinned repos should *each* visibly answer that in their description line.

## 2. Founder-voice specific patterns

### 2a. What founders DO that job seekers don't

| Pattern | Founder profile | Job-seeker profile |
|---|---|---|
| Bio is a verb ("Building X") | levelsio, leerob, sindresorhus | Lists languages |
| Pinned repos = shipped products | rauchg's `slackin`, leerob's `next-mdx-blog`, transitive-bullshit's `agentic` | Class projects, tutorials, clones |
| Repo description = product tagline | "Your API ⇒ Paid MCP. Instantly." (agentic) | "My React project for CS class" |
| Live URL in repo description | Yes (rauchg, leerob) | No URL at all |
| Profile README absent or minimal | leerob, levelsio, jamiebuilds, torvalds | Full "Hi 👋" template |
| No skill badges | All confirmed founders | jdhao-style badge grids |
| No "Languages I know" grid | All founders | Almost every junior profile |
| Twitter/website link in profile | Always | Sometimes (LinkedIn instead) |
| Sponsor button | rauchg, leerob, transitive-bullshit, sindresorhus | Off |

The Codeboards 2026 guide states this directly: *"Lead with who you are, not what you know"* and warns *"the most common mistake is treating your README like a resume dump."* ([Codeboards guide](https://codeboards.io/blog/github-profile-readme-guide))

### 2b. What founders OMIT — and why each omission matters

From the Codeboards guide and Fonzi.ai:
- ❌ "Animated text effects and flashy GIFs" → *"make your profile feel unserious"*
- ❌ "Visitor counters" → *"signal insecurity, not success"*
- ❌ Long badge walls → "say nothing"
- ❌ Skill stack grid → unverified self-claim; recent-language breakdown (auto-generated from real commits) is the only credible version
- ❌ "Open to opportunities" / "Looking for internships" → inverts the power dynamic
- ❌ Resume PDF in repo
- ❌ Graduation year, GPA, classes
- ❌ Daily-streak counter widget — pure vanity
- ❌ "Tech stack" emoji icons (the multicolor shields.io row)

The Hacker News thread of hiring managers is brutal about resume-driven repos: *"Someone with a perfect repository is either faking it or has never taken enough chances"* (edw519). ([HN thread](https://news.ycombinator.com/item?id=16224401))

### 2c. What founders ADD that signals scarcity

- A personal website on the profile (not a LinkedIn link — a *site they built*)
- Twitter/X link with a real handle
- One concrete affiliation in the company field (`Cursor` for leerob, `Linux Foundation` for torvalds, `Signal App` for jamiebuilds). For Naomi: `Sabi` or `Education for Equality`.
- A sponsor button if eligible (signals "people pay me for my work")
- Pinned repos with live URLs in the description
- A short, present-tense bio (`Building X` reads as in-motion; `Founder of X` reads as static)

### 2d. The "I'm valuable, you're recruiting me" stance in formatting

The framing flip:
- "Hi, I'm Naomi, a CS junior at Wesleyan looking for SWE internships" → JOB SEEKER
- "Building Sabi — voice AI tutor for Nigerian schoolchildren on dumbphones" → FOUNDER

Notice what's missing from the founder version: no "I'm," no school, no role description, no ask. The reader has to figure out who you are by looking at what you *do*. That asymmetry is the scarcity signal. This pattern is consistent with every founder profile I fetched: **the bio describes the work, not the person.**

Based on synthesis of the [Codeboards guide](https://codeboards.io/blog/github-profile-readme-guide), [gittohire 2026](https://gittohire.com/blog/optimize-github-profile-job-hunting-2026), [Rekort GIF guide](https://rekort.app/blog/gif-for-github-readme), and what's actually in rauchg's/transitive-bullshit's top repos:

# Sabi

Voice AI tutor for Nigerian schoolchildren on basic phones.
Call a number, talk to it, learn to read.

→ Live: https://sabi.app
→ Demo (60s): https://sabi.app/demo.mp4

![demo](docs/demo.gif)

## What it does
A child calls a Nigerian number. The system answers, runs a phonics
lesson, listens to them read aloud, and adapts to where they're
struggling. Works on a $20 Nokia.

## How it works
Twilio → Whisper (STT) → Claude Haiku (tutor loop) →
Chatterbox (voice clone TTS) → back to Twilio. ~700ms loop.

Self-hosted on a single Hetzner GPU box. Supabase for lesson state.

## Stack
Next.js · Twilio · Claude · Whisper · Chatterbox · Supabase · Hetzner

## Run it locally
```bash

cd sabi && pnpm install

```

## Status
~3,200 lesson minutes served. 2nd place MIT AI Hack 2026 ($3K).

Key choices verified against patterns:
- **One-line opener** then a couplet describing the experience — matches rauchg's `slackin: "Public Slack organizations made easy"` and transitive-bullshit's `agentic: "Your API ⇒ Paid MCP. Instantly."`
- **Live URL above the fold** — confirmed best practice by [gittohire](https://gittohire.com/blog/optimize-github-profile-job-hunting-2026)
- **GIF over screenshot, screenshot over nothing, video as a *link* (not embed)** — GitHub doesn't render inline `<video>` for most repos, but GIFs play everywhere ([Rekort 2026](https://rekort.app/blog/gif-for-github-readme))
- **"How it works" in 2-4 sentences with arrow notation** — current AI-native pattern (transitive-bullshit's agentic, swyx's smol-ai/developer)
- **No badge wall at the top.** The Codeboards guide explicitly calls these out.
- **Run-it-locally as a 4-line block.** Recruiters won't actually run it but the *presence* of "can I clone and go?" signals shipped vs. demo-ware.
- **Status section with verifiable numbers and prize results** — Devpost guidance encourages this ([Devpost help center](https://help.devpost.com/article/104-announcing-winners))

### 3d. Tone choice — first person vs. imperative
Verified across the founder set:
- rauchg's repos: imperative descriptions ("Public Slack organizations made easy")
- transitive-bullshit: imperative ("Your API ⇒ Paid MCP. Instantly.")
- leerob: descriptive ("Get started quickly with Next.js, Postgres, Stripe")
- levelsio: first-person in bio, descriptive in repo descriptions

**Recommended for Naomi**: descriptive repo descriptions ("Voice AI tutor for…"), first-person only in the inside-the-README "Why I built it" section if used. Never write "I am a junior at…" in a project README.

### 3e. Code-quality signals (badges)
Worth keeping (low noise, real signal): CI status (`![CI](.../actions/workflows/ci.yml/badge.svg)`), license badge, npm version if published. Worth dropping: Made with ♥ badges, Maintained — yes! badges, anything from shields.io that isn't auto-generated from real data. Codeboards: *"Codeboards badges as superior to manual skill claims… distinguishing verified activity from assertions"* ([Codeboards](https://codeboards.io/blog/github-profile-readme-guide)).

### 4d. The public/private/archive/delete decision matrix

Verified guidance from [Dina Berry's cleanup post](https://dfberry.github.io/2025-12-30-github-account-clean.md), [boot.dev](https://www.boot.dev/blog/jobs/build-github-profile/), [Codegenes on contribution preservation](https://www.codegenes.net/blog/does-removing-a-github-repo-also-remove-the-git-contribution-history-from-the-chart-on-your-profile-page/):

| Repo type | Action | Reasoning |
|---|---|---|
| Shipped product, alive | **Public + pin** | Trophy case |
| Shipped product, dead | **Public, archive flag ON** | Preserves history; signals "completed work" not "abandoned" |
| Hackathon winner | **Public, README updated with prize** | Devpost link in README, prize callout above the fold |
| Hackathon non-winner with cool tech | **Public, README updated** | Frame as "shipped in 24hrs" — speed is a signal |
| Class project / tutorial follow-along | **Make private** (do NOT delete) | Contributions preserved on graph ([Codegenes](https://www.codegenes.net/blog/does-removing-a-github-repo-also-remove-the-git-contribution-history-from-the-chart-on-your-profile-page/)) |
| Empty/stub repo | **Delete** | Worst signal — looks careless |
| Forks you didn't really modify | **Delete or unstar** | HN thread: "easy to spot, makes you look like you padded the profile" |
| Old experiments with cool code but bad READMEs | **Either: (a) write a real README now, or (b) make private** | "Cool code, no README" reads as a half-finished project |
| Naomi.dev / personal site repo | **Public, no pin** | Standard expectation |

Important: deleting a repo does NOT remove its commits from your contribution graph as long as the commit emails match your account ([Codegenes verified](https://www.codegenes.net/blog/does-removing-a-github-repo-also-remove-the-git-contribution-history-from-the-chart-on-your-profile-page/)). So you can safely make embarrassing-but-active repos private without losing the green squares.
