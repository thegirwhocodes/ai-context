# Academic Feedback & Formatting Preferences

## Explanation Style
- **Explain like she knows nothing**: "from now on, explain to me like I don't know anything about finance" — default to beginner-level explanations
- **Use analogies**: Pizza shop analogy for liquidity exposure was well-received; use real-world analogies for abstract financial/economic concepts
- **Step by step**: Prefers walkthroughs that build concept on concept, not dumping everything at once
- **Show visual aids**: ASCII diagrams for yield curves, Solow diagrams, etc. are appreciated
- **Comprehensive**: Wants full chapter/lecture walkthroughs, not summaries — cover everything

## Homework Formatting
- **Show all workings**: "the professor likes us showing all our workings" — keep full math derivations
- **Remove AI language**: "remove any elaborate answers that look like Claude wrote it" — trim overly polished vocabulary, textbook-style phrasing
- **Use only class patterns**: "redo the homework, but using the examples used in the classes" — don't use functions/methods not taught in class (e.g., don't use `.fillna()` if it wasn't in class notebooks)
- **No LaTeX**: Her markdown viewer doesn't render `$$` blocks — use plain text math with Unicode symbols (subscripts, arrows, inequality symbols)
- **Natural voice**: Use casual connectors ("so", "pretty similar"), shorter sentences, no fancy vocabulary
- **Keep spacing clean**: Prefers tight spacing between sub-questions within the same problem; blank lines only between main questions

## Workflow Corrections
- **Research before answering**: "can you google it before going all rapid fire" — look up information before giving instructions
- **Don't assume**: Check actual files, class notebooks, and syllabi before advising
- **Don't claim inability**: "YES you have access to them, don't tell me you don't" — she expects Claude to search thoroughly before saying it can't find something
- **Check class materials first**: Always reference lecture slides and class notebooks to match professor's approach
- **Undo support**: She frequently asks to undo changes — keep track of previous versions when editing files

## Problem Set Submission Style
- Prof. Kuenzel (Econ 349): Show all workings, neat math, avoid AI-sounding language
- Econ 241 (Prof. Imai): Problem sets with solution keys available — study from those
- QAC 386: Submit Jupyter notebooks (.ipynb) via Moodle — code should match class coding patterns exactly
