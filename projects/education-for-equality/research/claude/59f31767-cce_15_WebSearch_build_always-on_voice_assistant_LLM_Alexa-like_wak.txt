## Core Architecture

Every voice assistant runs the same five-step pipeline, whether it ships from Amazon or you build it yourself, and getting the architecture right before you write code is important. The flow starts with a wake word detector listening for your trigger phrase, and when it fires, it hands a short audio buffer to a speech-to-text (STT) engine like faster-whisper running Whisper v3.

## Key Components

A fully offline voice assistant combines three main components: whisper.cpp for speech-to-text, a local LLM (Llama 3.1 8B, Phi-4, or Mistral 7B via Ollama) for reasoning, and Piper TTS for speech output.

For wake word detection specifically, you can add a wake word detector like OpenWakeWord or Porcupine to make the assistant always-listening without running Whisper continuously. Porcupine Wake Word enables always-on, hands-free activation for the voice agent, listening continuously with minimal CPU and battery usage.

## Conversation Architecture

The current approach sends each prompt in isolation, but wrapping it with a conversation history that passes previous exchanges to Ollama enables context-aware responses. A key optimization is streaming TTS output while the LLM is still generating rather than waiting for the full response, starting to speak the first sentence as soon as it's complete, which drops perceived latency to 8-12 seconds.

## Latency Performance

The end-to-end latency on a desktop GPU setup is 1–2 seconds, comparable to Alexa or Google Assistant, while on a Raspberry Pi 5, it is 5–8 seconds — usable for hands-free queries, not conversational.
