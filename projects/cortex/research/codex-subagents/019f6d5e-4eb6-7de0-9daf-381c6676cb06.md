Once acknowledged, the outbox is cleared and the duplicate is skipped locally; no second request reaches the server. Server completed-checkpoint idempotence exists in code/tests, but the CLI discards the server’s `result.idempotent` value. See [export-imessage.mjs](/Users/naomiivie/cortex/.worktrees/cortex-integration-held/scripts/export-imessage.mjs:81).

- `probe` returns exit code 0 even for denied/missing/unknown permission states. Acceptance must match the JSON exactly; shell success alone is insufficient. Likewise, a permission-denied `run` can return a zero-exit summary with `health: "permission_denied"`. See [imessage-cli.ts](/Users/naomiivie/cortex/.worktrees/cortex-integration-held/local-bridge/src/imessage-cli.ts:62).

- `grant --keychain-prompt` stores or replaces the Keychain item before validating all source/device/endpoint arguments. Verify every value before invoking it; a failed grant can leave an orphaned or replaced credential.

- The scanner contract says it receives the next sequence, but the process adapter always invokes it with `--sequence 1`; the durable engine independently computes the authoritative sequence/checkpoint. Operational safety is preserved, but the documented scanner invocation is inaccurate. See [imessage-adapter.ts](/Users/naomiivie/cortex/.worktrees/cortex-integration-held/local-bridge/src/imessage-adapter.ts:145).

## Cleanup

After evidence is retained and only if this is a dedicated staging device:

1. Confirm `pendingUpload: false`; never revoke while an outbox is pending unless intentionally discarding it.
2. Run local `pause`, then Pause and Remove the staging source in the signed-in UI.
3. Run local `revoke`; this removes local consent and per-source state:

```sh
npm run bridge:imessage -- revoke --source-id '<SOURCE_UUID>'
```

4. Revoke the dedicated server device through the authenticated same-origin `DELETE /api/integrations/local/devices` route. The current UI has no device-revoke control.
5. Delete the exact Keychain item:

```sh
security delete-generic-password \
  -s com.cortex.local-bridge.device-token \
  -a '<LBD_DEVICE_ID>'
```

6. Disable Terminal’s Full Disk Access and restart Terminal.
7. Obtain the user temp directory with `getconf DARWIN_USER_TEMP_DIR`; verify no `cortex-imessage-*.db` files remain. Delete only confirmed orphan scanner snapshots after all bridge/scanner processes have stopped.
8. Preserve `identity.json` and the content-free audit until evidence is archived. Local `revoke` intentionally does not remove them.
