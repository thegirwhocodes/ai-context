## Blocking Application Execution

The `ES_EVENT_TYPE_AUTH_EXEC` event allows your application to take action against a process before it executes, potentially blocking a process from executing.

## How It Works

When your application receives messages from the client, if it is an auth event, you can handle those cases by queuing up the messages and handling them based on conditions set by the application. Because all of this is handled without leaving the kernel, if your application is set up to block that process, it can be halted before executing.

## Authorization Response

Clients can respond with `ES_AUTH_RESULT_DENY` to prevent the action or `ES_AUTH_RESULT_ALLOW` to allow it.

## Implementation Example

You can use a simple string comparison on the new process that will be executing, then compare that signing ID to the one that you want to block. By looking at the event-specific data in the event union and pulling out the signing_id data, you can compare that to the signing_id_to_block, and if they're equal, you can respond with the `es_respond_auth_result` API to deny it.

## Key Considerations

It is recommended that your ES clients perform as little work as possible in their event handler block, typically meaning you shouldn't perform a lot of I/O or large CPU-intensive tasks.

This approach would be suitable for building a distraction blocker that prevents specific applications from launching based on criteria like signing ID, file path, or other process characteristics.
