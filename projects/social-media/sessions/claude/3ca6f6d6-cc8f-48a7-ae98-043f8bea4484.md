Here’s a clear, practical way to think about building one—from simple to more advanced.

🧠 1. The simplest agent (LLM + loop)
At its core, an agent is just:

Brain (LLM like GPT)

Memory (optional but important)

# AI Agent Framework Comparison for a Desktop Video-Editing Agent (2026)

## 1. Claude Agent SDK (Anthropic)

**Core architecture.** The Claude Agent SDK (renamed from "Claude Code SDK" in Sep 2025) exposes the same harness Claude Code itself runs on: a main agent loop with tool use, optional subagents, a filesystem as context, persistent memory (`CLAUDE.md` + `/memory`), hooks (PreToolUse, PostToolUse, SessionStart, Stop, SubagentStop, UserPromptSubmit), slash commands, and first-class MCP client support. Tools are declared as JSONSchema or imported from MCP servers; the SDK manages tool-call loops, partial JSON streaming, and interrupts. Available in TypeScript (`@anthropic-ai/claude-agent-sdk`) and Python (`claude-agent-sdk`).

**Memory/state.** Three layers: (1) the conversation itself, (2) automatic `CLAUDE.md` auto-load on session start, (3) explicit `/memory` file edits by the agent. Session transcripts persist to disk — resumable via `--resume &lt;session_id&gt;`. Context editing + 1M context window on Sonnet 4.5 / Opus 4.7 mean long-running agent sessions don't require you to hand-roll a vector DB for working memory.

**Streaming.** Native SSE streaming of text + tool use blocks. The `query()` async iterator yields `AssistantMessage`, `ToolUseBlock`, `ToolResultBlock`, `ThinkingBlock` — easy to pipe into a UI.

**Best fit.** Anything where the agent needs filesystem access, long-horizon planning, subagent delegation, or tool orchestration. The SDK is genuinely unmatched for "agent that operates on a user's machine."

**Gotchas.** Opinionated — you inherit Claude Code's system prompt conventions unless you override `systemPrompt: { type: "custom" }`. MCP server lifecycle is your problem (you must spawn/kill). Subagents don't share memory with the parent by default. Cost: Sonnet 4.5 at ~$3/$15 per MTok with prompt caching is cheap enough for a local app; Opus is 5x that.

**Docs.** https://docs.claude.com/en/api/agent-sdk/overview, GitHub: `anthropics/claude-agent-sdk-typescript` and `anthropics/claude-agent-sdk-python`.

## 2. OpenAI Agents SDK

**Core architecture.** Released March 2025 as the successor to Swarm. Primitives: `Agent` (LLM + instructions + tools), `Handoff` (agent-to-agent transfer as a tool call), `Guardrail` (input/output validators, run in parallel), and `Runner` (loop). Supports MCP since mid-2025. Built-in tracing dashboard at platform.openai.com.

**Memory/state.** Thinner than Claude's. Conversation state is a list passed to `Runner.run()`; you persist it yourself. OpenAI's Responses API does have a server-side `previous_response_id` chain, but it's not durable long-term memory.

**Streaming.** Yes, via `Runner.run_streamed()` — emits `RawResponsesStreamEvent` and `RunItemStreamEvent`.

**Best fit.** Multi-agent workflows where handoffs are the natural abstraction (customer service → specialist, triage → worker). Great if you're GPT-5 / o4-locked.

**Gotchas.** Weaker filesystem / coding primitives than Claude SDK — no "here's a checkout of files, go edit them" pattern. No hooks equivalent. Less mature MCP tooling. Tracing is proprietary.

**Docs.** https://openai.github.io/openai-agents-python/, GitHub: `openai/openai-agents-python` and `openai/openai-agents-js`.

## 3. LangGraph

**Core architecture.** A graph executor where nodes are functions (usually LLM calls) and edges are conditional transitions. You define a `StateGraph` with a typed state dict; nodes mutate state. Supports cycles, subgraphs, and parallel branches.

**Memory/state.** Best-in-class. `Checkpointer` (SQLite, Postgres, Redis) snapshots state at every step — you get time travel, replay, and human-in-the-loop interrupts via `interrupt()` for free. `Store` API for long-term cross-thread memory with namespaces.

**Streaming.** Token, node-event, and state streams via `graph.astream()` with `stream_mode`.

**Best fit.** Complex, branchy pipelines with explicit control flow — think "analyze video → if score&lt;0.7 retry with different prompt → else render → HITL review." Your 3-variations-and-pick-best loop maps directly to a LangGraph cycle.

**Gotchas.** Verbose. You write a lot of node/edge code for things Claude SDK gives you free. Not tied to any model provider (pro and con). The learning curve is the steepest on this list.

**Docs.** https://langchain-ai.github.io/langgraph/, GitHub: `langchain-ai/langgraph`.

## 4. Vercel AI SDK

**Core architecture.** Not really an "agent framework" — it's a universal LLM client + React/Svelte/Vue hooks. v5 (Aug 2025) introduced `Agent` class with `stopWhen` loop conditions, typed tool calls, and agentic control primitives (`prepareStep`, `activeTools`). `streamText`, `generateText`, `streamUI` are the core primitives. `useChat` hook handles message state on the client with full SSE streaming of tool calls, reasoning, and data parts.

**Memory/state.** BYO — designed to be stateless on the server; the client holds message history. Pairs well with any backend memory layer.

**Streaming.** Unbeatable for UI. Multi-step tool calls stream incrementally; the client sees `tool-call-streaming-start`, argument deltas, results, all as they happen. Works in React Server Components.

**Best fit.** The UI layer of your Electron app. Do NOT use it as the brain.

**Gotchas.** Its "agent" abstraction is lightweight — no subagents, no checkpointing, no hooks. If you need orchestration, use it alongside something else.

**Docs.** https://ai-sdk.dev, GitHub: `vercel/ai`.

## 5. CrewAI / AutoGen / LlamaIndex Agents

**Short answer: largely superseded for your use case.**

- **CrewAI** — still alive, niche for "role-playing crew of agents" demos. Active community but the abstraction (Agent/Task/Crew with YAML) is brittle for filesystem-heavy agent work. Skip.
- **AutoGen** — Microsoft rewrote it as `autogen-core` + `autogen-agentchat` in late 2024; now part of the Magentic-One / Semantic Kernel orbit. Decent for research; in 2026 most teams have moved to LangGraph or OpenAI Agents SDK for production.
- **LlamaIndex Agents** — LlamaIndex itself is still the RAG/indexing leader. Its agent layer (`AgentWorkflow`) is usable but niche — use it if your primary problem is "agent over a giant document corpus." Not your problem.

## 6. MCP (Model Context Protocol)

**Status in 2026.** MCP has become the de-facto tool-interop standard. Anthropic, OpenAI, Google (Gemini), Microsoft Copilot, and Cursor all ship MCP clients. Servers expose `tools`, `resources`, `prompts`, and (since late 2025) `sampling` + `elicitation`. Transport: stdio (local) and streamable HTTP (remote, replaced SSE).

**Dynamic discovery.** Yes. MCP clients can connect to servers at runtime, call `tools/list`, and expose those tools to the agent. Claude Agent SDK, OpenAI Agents SDK, LangGraph (via `langchain-mcp-adapters`), and Vercel AI SDK all support dynamic MCP connections.

**For your DaVinci Resolve MCP.** Any of the four frameworks can connect to it. Claude Agent SDK has the cleanest story — drop the server into `mcpServers` in SDK options and its tools are exposed automatically.

## 3. Proactive Behavior — Implementation Patterns

**File watching on macOS:** use FSEvents via `fswatch` or the Swift `DispatchSource.makeFileSystemObjectSource` API — far cheaper than polling. The daemon is a thin Python process that watches folders and enqueues jobs into a local SQLite-backed queue (`sqlite-utils` or just a `jobs` table). The Electron app reads the queue and pulls results when open. This is how Rewind, Raycast, and Granola all work — lightweight daemon + rich UI app that talks to it.

## 4. Personalization That Feels Genuine

**Hybrid memory architecture** (this is what Sana, ChatGPT, and Claude Projects all converge on):
- **Symbolic layer (SQLite/JSON):** structured facts. `user.preferred_lut = "Naomi_Worship_Warm"`, `user.caption_style = "submagic"`, `user.avg_cut_length_seconds = 3.2`. Fast, explainable, editable in UI.
- **Vector layer (Chroma / LanceDB / sqlite-vss):** embeddings of past conversations, past edit decisions, past feedback. "Find me times the user rejected a suggestion like this."
- **Episodic log:** raw chronological transcript of interactions with timestamps. The ground truth for re-deriving everything else.

**Memory writes — when, what, how much.** ChatGPT's rule (and the right one): write memory **only when the user says something durable about themselves or expresses a preference**. ## Part 1 — State of the art in AI video editing agents (2026)

### 1. Submagic
Submagic is a thin-but-good wrapper over a standard pipeline, not a research lab. The architecture, as best as has been disclosed through their blog/marketing and reverse-engineering from output behavior:

- **ASR layer**: Whisper-family word-level transcription (very likely WhisperX or a proprietary fork) for the sub-100ms timing their animated captions need. They auto-detect language across 50+ languages.
- **Caption styling layer**: a template engine, not AI — the "viral templates" (MrBeast, Hormozi, Ali Abdaal, etc.) are hand-designed After-Effects-style compositions keyed off word timestamps. The "AI" part is mostly: (a) picking which word to emphasize (heuristic: keyword extraction + length + audio energy), (b) emoji insertion via a small LLM that reads the transcript and suggests contextual emoji per phrase, (c) B-roll suggestion via CLIP-style text→stock-video search against a Storyblocks/Pexels index.
- **Virality / hook detection**: they added an "AI Hooks" feature that is an LLM (almost certainly GPT-4o/Claude class) reading the transcript and rewriting the first 3 seconds.
- **Clipping (Magic Clips)**: long-form → shorts uses an LLM over the transcript to find self-contained "moments," similar to Opus, but weaker — reviewers consistently rate Opus above it for clipping quality.
- **Pricing (2026)**: ~$16–$49/mo depending on minutes. No public API.

The "wow" is that their caption templates are genuinely beautiful and their word-sync is tight. Everything else is commodity.

### 2. Opus Clip
The clearest "agentic" SaaS in this space. Their publicly-claimed stack, called **ClipAnything** / **ClipGenius**:

- **Transcript-first**: Whisper-class ASR, then a fine-tuned LLM (they've said they use an ensemble including OpenAI + their own model) segments the transcript into candidate clips by detecting complete narrative arcs — "hook → tension → payoff." This is the piece most competitors fake.
- **Virality Score (0–100)**: regression model trained on a dataset of ~1M+ TikTok/Reels/Shorts clips labeled with view counts, watch-time, and engagement ratios. Input features they've hinted at: (i) hook strength from LLM scoring the first sentence, (ii) speech energy / pitch variance from the audio, (iii) face presence and emotion (FER) per second, (iv) scene-change density, (v) caption density, (vi) completeness of the narrative arc from the LLM, (vii) topic embeddings matched to currently-trending topic clusters. The score is marketing-grade — directionally useful, not literally predictive — but the underlying features they compute are genuinely the right ones.
- **Layout Agent ("AI Reframe")**: active-speaker detection (face + lip-sync correlation) drives a 9:16 crop. This is now table-stakes and uses standard face-tracking (RetinaFace / YuNet) + a Kalman-filter smoother.
- **Pricing**: ~$19–$79/mo, with an API now available for agencies via their "Opus Clip API" beta.

### 3. Vizard, Veed, Captions.ai, Descript
- **Vizard** — direct Opus competitor for clipping long videos. Weaker virality model, but cleaner B-roll insertion from stock libraries. Wow moment: batch-processing a whole podcast backlog.
- **Veed** — browser NLE + AI features bolted on. Their "Magic Cut" removes silences (basically `auto-editor` dressed up) and "Eye Contact" does a gaze-correction GAN so the speaker always looks at camera. That's the genuine wow — it's one of the few places you'll see a real generative model (a gaze-aware face reenactment model, likely a thin fine-tune of something like LivePortrait or a Diffusion-VAE variant) inside a mainstream editor.
- **Captions.ai** — the most interesting agent. Features: "AI Creator" (generate a talking-head video end-to-end from a script using a trained avatar of yourself), "AI Edit" (applies viral-style captions + zooms + B-roll), and "Twin" (voice+face clone). They fine-tune their own models; they shipped "Mirage" in 2024, a controllable face/voice cloning model. The wow is the combination of your own avatar speaking a script.
- **Descript** — the odd one out. Transcript-driven editor: you edit the video by editing the text. Their "Underlord" is an LLM agent that watches your session and suggests cuts, removes filler, writes chapter titles, and proposes B-roll. Closest thing on the market to what you're building, but it's a full NLE, not a desktop agent. Pricing: $12–$24/mo.

These are generation labs. They've each started shipping editing-adjacent features:

### 5. Research + open source (2024–2026)
Relevant papers and models for the "understand a 30-min video and pull the best 60 seconds" problem:
- **LongVU (Meta, 2024)** — spatiotemporal adaptive compression for hour-long video understanding. Most directly applicable to long-form clipping: it keeps token count tractable while retaining fine temporal detail. Check against their code on GitHub.
- **Gemini 1.5 / 2.0 / 2.5 Flash** (what you already use) — still the most practical tool for "watch and reason over" full videos, with 1M+ context tokens. 2.5 Flash is the right default for cost. This is genuinely SOTA for the understanding step — better than building your own.
- **VideoLLaMA 2/3, PLLaVA, Video-ChatGPT** — open-source alternatives if you ever want to self-host. All weaker than Gemini 2.5 for dense temporal grounding, but VideoLLaMA 3 is closest.
- **InternVideo2, V-JEPA 2 (Meta)** — strong video encoders for feature extraction (good for a virality regressor if you build one).
- **TimeChat, Momentor, HawkEye** — papers specifically on "moment retrieval" (given a query, find the timestamp) — directly relevant to "find the best 60 seconds."
- **CLIP4Clip / X-CLIP / VideoMAE-v2** — older but useful for embedding-based highlight selection.

Open-source video tooling you'll actually import:
- **PySceneDetect** — shot boundary detection (ContentDetector / AdaptiveDetector). Free and reliable.
- **auto-editor** — silence/pause removal, scriptable. Good MVP backbone.
- **WhisperX / CrisperWhisper** — you already have these.
- **RetinaFace / MediaPipe Face Mesh** — face presence + landmarks for "is Naomi on-screen."
- **py-feat or EmoNet** — facial emotion per-frame (cheap proxy for "engagement peaks").
- **librosa / pyloudnorm** — speech energy and RMS envelopes.
- **FFmpeg** — your render engine, already planned.

There's no "understand a 30-min video and pull the best 60 seconds" SOTA model you can drop in — it's always a pipeline. Gemini 2.5 Flash over the full transcript + audio-derived energy + face/emotion peaks + scene changes, composed into a scoring function, is the actual SOTA approach. That's what Opus Clip does under the hood.

### 6. Virality / retention scoring research
There is real research; most of it comes from academic labs and TikTok/Meta directly:
- **TikTok's public blog + their 2021–2023 engagement papers** describe the signals their ranker uses: watch-time ratio (rewatches + completion), shares-per-view, and early-drop-off at seconds 1–3. "Hook quality" is operationalized as retention at second 3.
- **"Viral Videos in Social Networks"** and follow-ups (UCLA, USC, CMU groups) find that pacing (cuts per 10s), caption density, face-on-screen fraction, and emotional arousal peaks correlate with retention — but effect sizes are modest and content-topic-dependent.
- **MrBeast's leaked production doc (2023)** codifies hook retention, "reset the attention" cuts every ~10s, and visual novelty as the three dominant retention levers. Not research but it's the most-cited practitioner framework.
- **What actually predicts retention well in practice** (from the creator-analytics work): hook strength (first 3s), pacing variance (not just density — variance), caption presence on mobile, speaker face-on-screen %, and musical/emotional peaks aligned to the first third. What does *not* predict well: production quality beyond a threshold, LUT choice, caption "style."

For Lumina: don't build a "virality score." Build the *features* (hook scored by an LLM, pacing, face %, emotion peaks, caption density, audio energy curve) and show them to Naomi as a dashboard. That's more honest and more useful than a single 0–100 number.

## Part 2 — Legally pulling Instagram videos into Lumina

### 1. Instagram Graph API (the current Meta API)
This is the one you'll use. It's the business-side API, lives at `graph.facebook.com/v21.0/...` and `graph.instagram.com/v21.0/...`.
- **Account requirement**: the Instagram account must be a **Business** or **Creator** account, and (for most scopes) it must be linked to a Facebook Page. As of late 2024 Meta opened a parallel "Instagram Login" flow (also called Instagram API with Instagram Login) that lets Creator accounts connect without a Facebook Page — this is what you want for Naomi and for scaling to other creators who don't have FB Pages.
- **Read user media**: endpoints `GET /{ig-user-id}/media` lists the user's own posts/Reels; `GET /{ig-media-id}?fields=media_url,media_type,thumbnail_url,permalink,caption,timestamp` returns a signed `media_url` that is a temporary CDN URL you can download. The `media_url` expires (short-lived, usually a few hours).
- **Scopes**: `instagram_business_basic`, `instagram_business_content_publish`, `instagram_business_manage_comments`, `instagram_business_manage_insights` (these are the post-2024 scope names on the Instagram Login flow; the older Facebook Login flow uses `instagram_basic`, `instagram_content_publish`, `pages_show_list`, `pages_read_engagement`, `business_management`).
- **Rate limits**: 200 calls/user/hour on the legacy limits; the newer Business Use Case rate limiting is a rolling budget based on your app's usage score. Media download itself is not counted against the Graph limits because you're hitting a CDN.
- **App Review**: required to use any non-trivial scope with non-test users. Timeline: typically 1–4 weeks. You'll need a working demo video showing the OAuth flow and what the app does with each permission. Data Use Checkup is annual.
- **Token expiry**: short-lived user tokens = 1 hour; long-lived = 60 days, refreshable indefinitely if exchanged before expiry.

### 2. Instagram Basic Display API
**Dead.** Meta sunset it on **December 4, 2024**. It's the main reason every indie Instagram tool scrambled in Q4 2024. The replacement is the **Instagram API with Instagram Login** path under the Instagram Graph API umbrella — same endpoints as Graph API but a simpler OAuth flow that doesn't require the user to have a Facebook Page.

### 3. Content Publishing API
Lives under the same Instagram Graph API. Two-step container flow:
1. `POST /{ig-user-id}/media` with `media_type=REELS`, `video_url=&lt;publicly reachable URL&gt;`, `caption=...`, optional `share_to_feed=true` → returns a container ID.
2. Poll `GET /{container-id}?fields=status_code` until `FINISHED` (usually 30–90s for Reels).
3. `POST /{ig-user-id}/media_publish` with `creation_id=&lt;container-id&gt;` → publishes.
- **Requirements**: Business or Creator account, `instagram_business_content_publish` scope, and the video file must be reachable from a public URL (S3, Cloudflare R2, even a signed tempfile URL — can't be localhost). For Lumina MVP: upload to a cheap bucket or use Cloudflare R2 free tier.
- **Rate limit**: **25 API-published posts per IG user per 24 hours** (this one has held steady; confirm in the docs).
- **Video specs for Reels**: MP4/MOV, H.264, AAC, ≤ 1GB, 3–90s (for Reels), 9:16 preferred, 30fps recommended, ≤ 4K. Bitrate: Meta recommends ≥ 5 Mbps.

### 4. Third-party aggregators
- **Ayrshare** — $149+/mo for business; hosted API that proxies posting to IG/TikTok/YouTube/LinkedIn/X. Cuts app-review work dramatically. Not free, so rule it out for your $0 MVP — but it's the fastest path when you onboard creator #2.
- **Buffer API** — available to Business-tier ($6/user/mo baseline, but API access is gated). Good fallback.
- **Later API** — limited external API; they really want you in their UI.
- **Meta Business SDK** — official Meta-authored SDK wrapping the Graph API. Use this for Lumina; it is the Graph API, not a separate service.

For a $0 MVP with one user (Naomi), **skip aggregators**. Go direct to Graph API.

### 5. What you cannot do
- **No personal-account access** without converting to Business/Creator. The old Basic Display workaround is gone.
- **No scraping** of instagram.com (blocked by TOS and actively rate-limited/banned; Meta has won lawsuits against scraper operators — BrightData, Bright Initiatives).
- **No unofficial libs** like `instagrapi`, `instaloader` against production accounts — they work by impersonating the mobile app, will get Naomi's account flagged or locked, and clearly violate TOS. Fine for personal experimentation on a throwaway account, not fine to ship in a product.
- **No DM automation**, no following/liking on the user's behalf, no reading other users' private content.
- **No downloading other people's Reels** via the API even if public.

The TOS line is clear: official Graph API, user consent via OAuth, documented scopes only.

### 6. Practical flow for Lumina (desktop)
Realistic plan for a local desktop app:
1. Register a Meta developer app (free). Configure it for Instagram API with Instagram Login.
2. In Lumina, "Connect Instagram" button launches the OAuth URL in the system browser, redirects to `https://localhost:PORT/callback` (use a local loopback server — Meta allows `https://` redirect URIs; use a self-signed cert or ngrok during dev).
3. Exchange the code for a short-lived token server-side (or in the app), then immediately exchange for a long-lived 60-day token. Store encrypted in the OS keychain (macOS Keychain via `keyring` in Python; Windows Credential Manager).
4. Set a background refresh every ~50 days to renew the long-lived token.
5. Fetch media list → download `media_url`s → hand off to the edit pipeline → upload edited result to a public URL (R2 free tier, 10GB free) → call Content Publishing API.
- **Gotchas**: (a) App Review is mandatory before non-dev users can connect. For Naomi-only, you can add her as a "Tester" in the app dashboard and skip review entirely — this is the right $0 MVP move. (b) Redirect URIs must be HTTPS; `http://localhost` is sometimes accepted in dev mode only. (c) Video upload for Reels is async — you *must* poll the container status; don't try to publish immediately. (d) Meta occasionally changes scope names and deprecates versions with ~90-day notice; subscribe to the Platform Changelog.

### 7. Alternatives for the scrappy MVP

- Naomi already has the raw `.MOV` files on her Mac (the worship video pipeline uses `IMG_9180_new.MOV`). The input side needs zero Instagram integration — just a file picker, which your Electron plan already has.
