# What it takes to build an excellent agent harness — the Granola pattern

*A deep synthesis based on primary-source research through September 2026. Links inline. Opinionated where the evidence supports it.*

---

## The one-line thesis

An excellent AI-agent harness is not a chat window or a graph of nodes. It is a **product surface built around one specific user moment**, wrapped in a **trust posture that matches the intimacy of what it captures**, that treats **your voice, format, and history as first-class procedural memory**, and that **pushes its output outward** into the tools you already use. Granola is the reference because every layer of it is legibly designed against those four constraints.

Chris Pedregal's own framing is the shortest version: Granola is a **steering wheel for chatbots** — the user provides intent, the AI provides horsepower ([Fast Company interview](https://www.fastcompany.com/91497900/granola-chris-pedregal-interview)). Every design pattern below is downstream of that.

---

## The anatomy of a harness — five layers

A harness sits between a raw model and a user's day. Cleanly separated, the layers are:

1. **Capture** — ambient audio (Granola), screen (Rewind, Cursor), text (Claude Code CLI), photos, calendar, email. The harness listens without being asked. The design decisions here are 90% about trust and 10% about codecs.
2. **Context** — everything the model needs to be useful about *you* right now: current calendar event, prior meetings with these people, your templates, your CRM records, your team's folder history. This is what makes the same LLM feel personal.
3. **Model orchestration** — model choice (routing across Anthropic/OpenAI/Google is Granola's default per [Cognitive Revolution](https://www.cognitiverevolution.ai/calm-ai-for-crazy-days-inside-granola-s-design-philosophy-with-co-founder-sam-stephenson/) and [Michael Goitein's teardown](https://michaelgoitein.substack.com/p/granolas-revolutionary-ai-strategy)), prompt caching, streaming, tool use, subagents, durable execution when the loop is long.
4. **Interaction** — where the user sits (a note surface, an editor, a terminal, a calendar sidebar), what steering primitives the harness offers (bullets, `/` templates, keyboard shortcuts), how much attention it demands during the moment vs. after.
5. **Distribution outward** — Slack, HubSpot, Notion, MCP for Claude/Cursor/ChatGPT to reach in ([Granola's MCP launch](https://www.granola.ai/blog/granola-mcp)). A harness that only writes to its own database is a walled garden and eventually loses.

Every excellent harness is opinionated at every layer. Every failed one was under-specified at one of them.

---

## The core mechanic Granola nailed — "you jot, we finish"

Granola's mechanic:

1. Native desktop app captures both microphone and system audio.
2. During the meeting, you type short bullets — 2% of your attention, per Sam Stephenson ([Cognitive Revolution podcast](https://www.cognitiverevolution.ai/calm-ai-for-crazy-days-inside-granola-s-design-philosophy-with-co-founder-sam-stephenson/)).
3. Real-time transcription runs via Deepgram + AssemblyAI in parallel ([Deepgram case study](https://deepgram.com/10-note-taking-ai-apps-for-productivity), [vulnu security writeup](https://www.vulnu.com/p/hard-coded-api-key-in-ai-note-taking-app-exposed-users-private-meeting-transcripts)).
4. When the meeting ends, the AI expands your bullets into a full note using the transcript, following a **template** you can edit like a Google Doc.
5. Enhanced notes cite the transcript. You can chat with them, run **recipes** ([TechCrunch on Recipes](https://techcrunch.com/2025/09/30/ai-note-taking-app-granola-adds-a-repeatable-prompts-feature/)) across meetings, and let a chosen reasoning model dig deeper.
6. Output ships automatically to Slack / HubSpot / Attio / Notion / your CRM ([Granola integrations](https://www.granola.ai/blog/granola-integrations-hubspot-slack-notion-zapier)).

What is load-bearing here is not the transcription. Half a dozen competitors have better speaker diarization. What is load-bearing is:

- **The bullet.** It is the single steering primitive the user hands the model. It is cheap for the human and rich for the AI.
- **The "after."** The heavy work happens post-meeting, so the meeting surface stays calm.
- **The template.** Your format, saved. Rerunable. Editable.
- **The trust posture.** Audio is never stored — desktop transcribes in real time and discards; mobile caches temporarily and deletes after post-processing ([Granola Security page](https://www.granola.ai/security)). SOC 2 Type 2 in July 2025. Enterprise training-off by default. Every claim on the security page is one sentence long and plainspoken.

Traction is downstream of these decisions: $192M raised across four rounds, $1.5B valuation, Series C led by Danny Rimer at Index in March 2026 ([Bloomberg](https://www.bloomberg.com/news/articles/2026-03-25/ai-notetaker-granola-hits-1-5-billion-value-in-125-million-funding), [TechCrunch](https://techcrunch.com/2026/03/25/granola-raises-125m-hits-1-5b-valuation-as-it-expands-from-meeting-notetaker-to-enterprise-ai-app/)), 250% quarterly revenue growth going into the Series C, "millions" of users. Angels are the founders of Vercel, Linear, Shopify, Replit, Ramp, Intercom — the people who themselves built excellent harnesses.

## The 14 harness patterns

Each pattern below has (a) what it is, (b) why it works, (c) reference implementations, (d) an honest failure mode. Cite an example from another product to keep it generalizable.

### 1. Ambient capture, opinionated trust posture

The harness is *there* the way a good assistant is there — capable of remembering everything, obligated to remember only what serves you.

- Granola: OS audio layer, works across Zoom / Meet / Teams / Slack huddles / in-person; audio never persisted.
- Limitless pendant: always-on ambient audio with a Consent Mode chime and 30-day auto-delete ([Limitless](https://www.limitless.ai/)).
- Rewind: local-first 24/7 screen recording — until Meta acquired them in December 2025 and shut those features off within days ([Screenpipe post-mortem](https://screenpipe.com/blog/rewind-ai-alternative-2026)).

The pattern is not "record everything." It is "record what serves the user, delete or never-store the rest, publish the model in plain English." The privacy story *is* the product; Otter's August 2025 federal class-action alleging surreptitious recording is the counter-example ([Index.dev meeting-tool comparison](https://www.index.dev/blog/otter-vs-fireflies-vs-fathom-ai-meeting-notes-comparison)).

**Failure mode:** capture without a strong consent posture becomes surveillance and eventually a lawsuit.

### 2. User-in-the-loop steering, not gate-keeping

The user provides *seeds* — bullets, examples, a template — and the agent expands them. The seed interface must be lighter than typing a prompt from scratch, or the user will just type the prompt.

- Granola's bullets are the canonical seed.
- Cursor's Rules for AI, Claude Code's CLAUDE.md, AGENTS.md — same pattern for code ([BuildBetter AGENTS.md vs .cursorrules vs Claude Skills 2026 comparison](https://blog.buildbetter.ai/agents-md-vs-cursorrules-vs-claude-skills-2026-comparison/)).
- Superhuman's snippet expansion, keyboard shortcuts as steering primitives for email triage.

**Failure mode:** wizards and multi-step forms as the steering surface. Users bail and revert to chat.

### 3. Post-processing beats real-time interruption

Real-time is the wrong rhythm for most work. Granola generates the *enhanced note* after the meeting — during the call the interface is deliberately dumb. Post-processing means the model can use the full transcript, run higher-quality (slower) models, and take a beat.

- Rewind's daily rollup, Limitless's daily summary, Granola's post-meeting enhancement all sit in the same rhythm.
- Claude Code has a similar rhythm at the command scope: think, plan, then act.

**Failure mode:** "AI chat during the meeting" surfaces (Copilot in Word during a call) interrupt more than they help. The human is already spending their attention on the human problem.

### 4. Personal templates as procedural memory

The harness needs to remember *how you like things done*.

- Granola's 29+ built-in templates + user-forkable + a **Recipes** library named after actual practitioners (Lenny Rachitsky's Write PRD, Matt Mochary's Coach me) — [TechCrunch on Recipes](https://techcrunch.com/2025/09/30/ai-note-taking-app-granola-adds-a-repeatable-prompts-feature/).
- Claude's Skills, ChatGPT Custom GPTs, Claude Projects, Warp Notebooks, Cursor Rules — same primitive, different domain.
- The BuildBetter distinction is useful: **rules are constraints, skills/templates are procedures**. Bloated CLAUDE.md files are usually procedures that should have been skills.

Granola's contribution is making this *legible to non-engineers*. Templates are just prompts you edit like a Google Doc. Recipes let you invoke a named coach's frame without touching config files.

**Failure mode:** treating templates as gates ("choose your persona before you start") trains users to skip them.

### 5. Progressive disclosure

Start simple, unlock power. Granola opens on a blank notepad next to your next calendar event; templates hide behind `/`; chat is a small icon; folders live in a sidebar you can ignore. Raycast starts as a launcher and reveals AI, extensions, and scripts as users grow into them. Linear starts as a clean list and progressively exposes projects, cycles, roadmaps, and triage — every capability is on a keyboard shortcut but not on the first screen.

**Failure mode:** kitchen-sink UIs (Otter's dashboard, most legacy CRMs) put every capability on the first screen and lose the user before day two.

### 6. Native-app performance

Perceived quality is a function of latency and frame rate. Raycast is the canonical case study: native shell + system WebView + Node backend + Rust core, single typed IPC schema, launches under 500ms, resident under 500MB ([Raycast's technical deep dive](https://www.raycast.com/blog/a-technical-deep-dive-into-the-new-raycast)). Linear ships in Electron but feels native — first paint under a second, every view instant. Superhuman built a $30/month email business on the same performance-as-brand thesis.

Granola is native on macOS and Windows precisely so the audio stack can stay tight and the note surface can feel like paper.

**Failure mode:** letting perceived latency creep past 200ms. Users can't articulate why they open the app less, but they do.

### 7. Trust as a first-class UI surface

Say what you store, where, who touches it, what happens if you leave. Granola's security page does this in one-sentence-per-claim plain English. Pedregal has publicly refused CEO requests for backdoor transcript access ([Platformer](https://www.platformer.news/granola-chris-pedregal-interview/)). Limitless bundles a Consent Mode chime for people around you. Granola offers an optional virtual-camera watermark so meeting participants can see the tool is active without a bot invading the roster.

**Failure mode:** ambient capture with vague or contradictory disclosure gets you a lawsuit (Otter), an acquisition-shutdown (Rewind), or a subway backlash campaign (Friend AI, September 2025 — [Webpronews on Friend backlash](https://www.webpronews.com/friend-ai-necklace-sparks-backlash-for-privacy-woes-and-tech-flaws/)).

### 8. Context accumulation

The harness gets smarter about *you* the more you use it. Granola 2.0's folder chat lets you ask "why are we losing deals?" across every call in a folder, with citations to specific transcript timestamps ([Granola 2.0 announcement](https://www.granola.ai/blog/two-dot-zero)). Briefs (May 2026) pre-generates a summary of prior conversations with the same attendee before your next meeting.

- Claude Code accumulates via CLAUDE.md and Skills.
- Cursor accumulates via rules and codebase indexing.
- ChatGPT Memory + Claude Projects sit at the same layer.

**Failure mode:** one-shot chatbots that start every session from zero. Users describe it as "forgetting on purpose."

### 9. Keyboard-first UX

In 2026 power users expect that anything they do twice becomes a shortcut.

- Granola: `/` for templates, `⌘K` for chat.
- Linear's `⌘K` command palette is the reference for the entire category.
- Raycast is a keyboard-first shell for macOS; Warp brought terminal shortcuts into an AI-native surface.
- Superhuman's shortcut ideology is the reason it stuck.

**Failure mode:** mouse-first AI apps (Otter's dashboard is the canonical example) never build the daily-driver muscle memory.

### 10. The "one great thing" thesis

Every harness that has stuck did one thing better than anyone thought possible before it moved outward.

| Harness | The one great thing |
|---|---|
| Granola | Turning your bullets into meeting notes |
| Superhuman | Email triage |
| Cursor | Agentic code edits inside a familiar editor |
| Linear | Issue tracking engineers actually want to open |
| Claude Code | Agentic terminal for developers |
| Perplexity | Fast answers with citations |
| Raycast | The launcher that swallowed macOS |

The failed harnesses started too broad. Humane wanted the AI Pin to replace your phone. Rabbit wanted the R1 to drive any app. Adept wanted an agent that ran the whole web ([Wikipedia: Humane Inc.](https://en.wikipedia.org/wiki/Humane_Inc.), [Wikipedia: Rabbit r1](https://en.wikipedia.org/wiki/Rabbit_r1), [Semafor on Adept–Amazon](https://www.semafor.com/article/08/02/2024/investors-in-adept-ai-will-be-paid-back-after-amazon-hires-startups-top-talent)). None had a moment where a real user thought "I could not have done this without this thing."

### 11. Streaming and caching for perceived responsiveness

Even async tasks feel better when they stream. Claude Code streams tool calls and reasoning so you can see it working. Perplexity streams tokens even when it doesn't need to. Granola shows transcript building in real time during the call, then streams enhanced notes when you stop.

Under the hood, **prompt caching** is the load-bearing technique. Anthropic's 5-minute and 1-hour caches drop cache reads to 10% of fresh-token cost ($0.30 vs $3.00 per M tokens on Claude), delivering **~90% cost reduction and ~85% latency reduction** on long-prefix prompts. Claude Code's team wrote a whole post about designing their harness around cache-friendly prefixes ([Lessons from building Claude Code](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything)). Structure: `[large static prefix — cache boundary — small dynamic suffix]`. Put system prompt + tool defs + user templates + prior notes at the top, put the user's current bullets at the bottom.

**Failure mode:** a spinner. A user watching a spinner is a user drafting the email that says "I tried it and it was slow."

### 12. Delightful defaults

Config-first harnesses lose. Ship it working:

- Granola: 29+ templates pre-loaded, calendar auto-connected on setup, sensible bindings, first-party recipe library.
- Linear picks a workflow for you.
- Superhuman configures your shortcuts on day one.
- Raycast pre-binds `⌥Space`.

Compare to Rabbit R1 shipping with a demo that promised the world and a home screen that showed four integrations.

### 13. Sync-first architecture

Real-time multi-device is table stakes. Linear + Figma are the reference model. Granola 2.0 syncs folders across devices, guest links work without an account, folder chat is multiplayer. Rewind stayed local-first for privacy and never solved "my notes are on my other Mac" — part of why Meta could quietly retire it.

**Failure mode:** "local files that sync via Dropbox." That was Bear and Obsidian's story, and both feel dated next to Notion, Linear, Granola in 2026.

### 14. Feedback loops from edits, not thumbs

The harness learns from what you edit. Granola's enhanced notes visibly re-run when you tweak the template; chat responses cite sources so you can push back with "no, that was Marcus, not Priya." Claude Code learns from CLAUDE.md changes. Cursor's rules evolve with your codebase.

**Failure mode:** thumbs-up/down as the entire feedback surface. It optimizes average model quality, not your specific use case.

## Anti-patterns from the harnesses that didn't stick

### Humane AI Pin (dead February 28, 2025)

$699 + $24/month, shipped April 2024. Marques Brownlee: "bad at almost everything it does, basically all the time" (8.5M views). Returns outpaced sales; charging case recalled for fire risk. HP acquired the assets for $116M in February 2025 and shut every Pin down 10 days later, deleting user data with the servers ([TechCrunch on HP acquisition](https://techcrunch.com/2025/02/18/humanes-ai-pin-is-dead-as-hp-buys-startups-assets-for-116m), [PetaPixel](https://petapixel.com/2025/02/19/humanes-ai-pin-is-dead-and-all-devices-will-stop-working-in-10-days/)).

**Anti-patterns:** shipped hardware without a "one great thing"; bet on a laser projector no one asked for; framed the phone as the enemy instead of the collaborator; had no story for what the harness did better than the phone in your pocket.

### Rabbit R1

Launched with a keynote demoing a Large Action Model that could "operate any app." Shipped with four integrations. Engadget: "a $199 AI toy that fails at almost everything." Rabbit has since pivoted twice — RabbitOS 2 in September 2025 with teach-mode where users record workflows, and 2026's "OpenClaw" / "Agent OS" umbrella ([Engadget: Rabbit's redemption arc](https://www.engadget.com/rabbit-plots-its-redemption-arc-120000271.html), [Yanko Design on OpenClaw](https://www.yankodesign.com/2026/03/23/rabbit-r1s-openclaw-update-could-be-its-most-important-moment-yet/)).

**Anti-patterns:** demoing capability the harness didn't have; betting on bespoke hardware where a phone app would have shipped in a week; unclear when-agent-vs-when-user (users didn't know if the LAM was doing the work or if they were tapping menus).

### Adept

Founded to build agents that operate any software. Shipped tech demos of ACT-1 driving Salesforce. Never shipped a product real users could adopt. Amazon acqui-hired the co-founders and most of the team in June 2024; investors got roughly their money back ([Semafor](https://www.semafor.com/article/08/02/2024/investors-in-adept-ai-will-be-paid-back-after-amazon-hires-startups-top-talent)). Amazon's own agentic team then lost its head of AGI lab in 2026 ([GeekWire](https://www.geekwire.com/2026/head-of-amazons-agi-lab-is-leaving-in-latest-exit-from-high-profile-adept-deal/)).

**Anti-patterns:** research-first, product-second; no surface where a user could get to "I love this"; foundation-model dependency that forced more fundraising than building.

### Otter / Fireflies / Fathom / tl;dv

The bot-in-the-meeting cohort. Real usage, real customers, but their product story is compressing. Otter faces a federal class-action alleging surreptitious recording (August 2025). None have made the "no bot in the meeting" leap; Granola's category shift left them defending the transcript-dump paradigm against a product users describe as their notepad, not their transcript archive.

**Anti-patterns:** dumping raw transcripts as the product; treating summaries as the value ceiling; letting the bot-avatar in the meeting become an anti-signal about the tool's stance toward user privacy.

### Friend AI necklace

$129 always-on pendant launched with a seven-figure NYC subway ad campaign in September 2025. Commuters wrote "dystopian" and "creepy" on the ads. Reviews describe an AI companion that "bullies" users ([Tech Buzz review](https://www.techbuzz.ai/articles/friend-ai-necklace-review-the-129-wearable-that-bullies-you)).

**Anti-patterns:** always-on with a soft consent story; an emotional-companion promise the model cannot keep; a launch strategy that made the privacy problem the marketing problem.

### Arc

Not a trust failure — a scope failure. Beautiful browser, tiny fanbase, sunset May 27, 2025; The Browser Company pivoted to Dia (AI browser), Atlassian bought them for $610M in September 2025 ([Wikipedia: Arc](https://en.wikipedia.org/wiki/Arc_(web_browser))). The lesson isn't "don't make a browser." It's that even a great design language cannot compensate for a product that redefines the metaphor faster than users can adopt it. Granola's counter-move — keep the notepad metaphor, change what the notepad does — is the correct one.

## Practical build path — how to actually construct one

If you were building a Granola-shaped harness today for a specific domain, the ordering matters. Skipping steps is where teams die.

**Step 0 — Find the moment.** Pick one specific user moment where the current answer is unaided attention (a meeting, a coding session, an email triage pass, a research session). "One great thing" means "one specific moment served better than anywhere else."

**Step 1 — Design the steering primitive.** What's your bullet? Granola picked a bullet you type during the meeting. Cursor picked a comment you write in code. Claude Code picked a natural-language prompt in a familiar shell. The primitive must be cheaper to hand the model than typing a prompt.

**Step 2 — Nail capture and trust.** Before writing an LLM prompt, decide: what do we store, where, who touches it, what happens on delete. Publish it in one-sentence-per-claim plain English on a public page. SOC 2 later; the plain-English page comes first.

**Step 3 — Ship a native surface.** Electron is fine (Linear, Slack); Tauri is better on memory; Swift/SwiftUI + macOS APIs unlock ScreenCaptureKit and Core Audio taps if you need system audio. Do not ship the primary surface as a web app if perceived latency matters — and it does.

**Step 4 — Build the context layer before you tune prompts.** The harness's edge isn't the prompt; it's *what's in the prompt on turn one*. That means: calendar, prior meetings/sessions with the same participants, the user's templates, their team's folder history, the CRM record. Retrieval + prompt caching in that order.

**Step 5 — Design templates and recipes for non-engineers.** Templates are user-editable prompts; recipes run *across* accumulated data. Give the user 20–30 delightful defaults on day one. Ship a marketplace once the pattern lands (Granola waited until Recipes in September 2025 — 16 months after launch).

**Step 6 — Route models, don't marry them.** Dynamic model routing across Anthropic / OpenAI / Google is what Granola does. Use `provider/model` strings via a gateway (Vercel AI Gateway or OpenRouter) so switching is a config change ([Vercel AI Gateway](https://vercel.com/docs/ai-gateway), [OpenRouter](https://openrouter.ai)). For reasoning-heavy steps expose the choice to the user, like Granola 2.0 does for folder chat.

**Step 7 — Instrument prompt caching from day one.** Structure prompts as `[static prefix — cache breakpoint — dynamic suffix]`. Put system prompt + tool defs + user templates + relevant history above the break. On Anthropic that's a 10× discount on the prefix. Expect ~90% cost reduction on your steady-state traffic.

**Step 8 — Durable execution as the loop gets long.** If your harness has more than three tool calls and a user might close the app, you need durability. Options: Vercel Workflows / eve, Inngest, Temporal, Restate. Do not build this in application code. See [Inngest's writeup on durable execution for AI](https://www.inngest.com/blog/durable-execution-key-to-harnessing-ai-agents).

**Step 9 — Ship outward.** MCP endpoint so Claude / ChatGPT / Cursor can reach into your harness. Native integrations with the tools your users already push output into — Slack, HubSpot, Notion, CRM. Zapier for the long tail. This is not optional; a harness whose output only lives inside its own app is a walled garden and will lose.

**Step 10 — Feedback loops from real edits.** Log every user edit to a generated note or output. Feed those edits back into template refinement — automated where it's safe, surfaced-to-the-user where it isn't. Anthropic's Sonnet 4.5 context editing and memory tool are the reference for how the model side of that loop should look ([Anthropic on effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)).

**Step 11 — Delightful defaults, then progressive disclosure.** Templates preloaded. Calendar auto-connected. Sensible bindings. Reserve advanced features (folders, chat, agents, custom models) for keyboard shortcuts and sidebar affordances.

**Step 12 — Say no more than yes.** Granola shipped 2.0 (folders + chat), Recipes, HubSpot, and MCP over the course of ~18 months. Everything else — Salesforce direct, deep transcript search UI, multi-language ASR polish, a Rewind-style desktop rollup — was said no to. The one great thing gets better before the second thing arrives.

## The distilled thesis

Granola works because:

- It **does one great thing** — turning your bullets into meeting notes.
- It **demands ~2% of your attention** in the moment that matters.
- It treats **your voice, format, and style** as first-class procedural memory (templates, recipes).
- It has a **plainspoken trust posture** you can quote to your GC in one paragraph.
- It **pushes its output outward** — Slack, HubSpot, Notion, MCP for Claude and Cursor to reach in.
- Under the hood it runs the industry-standard patterns — model routing, prompt caching, streaming, tool use, subagents, durable execution — but the user never has to know that.

Every harness that has stuck in 2026 — Cursor, Claude Code, Linear, Raycast, Superhuman, Perplexity — reads as a variation on that same set of decisions in a different domain. The ones that failed picked hardware they didn't need (Humane, Rabbit, Friend), capability they couldn't ship (Adept), or a stance toward user trust the market punished (Otter's class-action, Rewind's fate).

The formula isn't hidden. Building it is a design problem, not a modeling problem.

## Weight math — will beat Granola

| App | Runtime | Installed size | Idle RAM |
|---|---|---|---|
| **Granola** | Electron (Chromium bundled) | ~200 MB | ~150–250 MB |
| **Cortex on Tauri** | WKWebView (system, not bundled) | ~15–25 MB | ~40–80 MB |

Tauri uses macOS's built-in WebView, so we ship Rust + a config, not a whole browser. **Cortex will be measurably lighter than Granola** on both counts, without giving up the web codebase.

## The simplest 6 steps to a running `.app`

Nothing here changes the deployed website — just adds the shell around it. I want your sign-off before I touch any of it.

1. **Add Tauri to `package.json`** — `@tauri-apps/cli@^2` + `@tauri-apps/api@^2` in devDeps, and three scripts: `tauri:dev`, `tauri:build`, `tauri` (passthrough). One small commit, zero behavior change to the web app.
