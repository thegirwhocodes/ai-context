## Codex · 2026-07-07T18:48:48.609Z · final_answer

**Sync** means: Sabi sends one audio file to Intron and waits on that same request until Intron returns the transcript.

Flow:

```text
Sabi uploads audio → Intron processes immediately → same request returns transcript
```

Good for us because it is simple and fast enough for turn-by-turn voice calls if latency is low. But our key currently gets blocked here:

```text
/file/v1/upload/sync → 403, needs integrator account
```

**Async** means: Sabi uploads the audio, Intron gives back a `file_id`, then Sabi has to keep checking another endpoint until the transcript is ready.

Flow:

```text
Sabi uploads audio → Intron returns file_id
Sabi waits/polls → asks status endpoint → transcript eventually appears
```

This works with our key. I tested it and got transcript `45`.

The tradeoff:

- **Sync:** cleaner for live calls, one request, easier latency control.
- **Async:** works now, but slower/more awkward because Sabi must upload, poll, handle queued status, handle rate limits, then continue the conversation.

For a normal phone tutor, **streaming STT** would be even better: audio flows live while the child speaks, and transcripts come back as speech happens. Our key can create a streaming session and send audio chunks, but it didn’t return the final transcript yet, so we need Intron’s help there.
