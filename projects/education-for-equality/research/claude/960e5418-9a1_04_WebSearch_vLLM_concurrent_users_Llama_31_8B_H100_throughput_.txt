## Throughput and Concurrent Users

For the H100, 16 concurrent requests achieves optimal throughput with a maximum throughput of 8.01 tokens per second.

## Batch Processing Impact

The throughput increases significantly with batching. When vLLM processes many requests concurrently with continuous (in-flight) batching, it reads each weight from memory once and reuses it across every sequence in the batch, shifting the workload from bandwidth-bound toward compute-bound, allowing per-request tok/s to stay roughly the same while aggregate throughput can climb 10–20x before compute saturates.

## Inference Optimization

vLLM uses PagedAttention (which is inspired by virtual memory and paging techniques used in operating systems), to manage the KV cache using blocks/pages, allowing vLLM to efficiently and dynamically utilize HBM memory and minimize memory fragmentation.

## Performance Comparison with Other Engines

Recent benchmarks comparing multiple inference engines show competitive performance. For Llama 3.1 8B batch inference on H100, vLLM (optimized with FlashInfer) provides a solid baseline, while the C++-native architectures of SGLang and LMDeploy unlock an additional 29% in throughput.
