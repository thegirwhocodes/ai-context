## **4. VIEW MODELS**

### `/Shared/ViewModels/FriendViewModel.swift`
**Class:** `FriendViewModel: ObservableObject` (MainActor)

**Published Properties:**
- `friends: [Friend]` - All friends
- `todayDue: [Friend]` - Friends to contact today
- `showCapacityError: Bool`
- `isSyncing: Bool`, `syncError: String?`
- `touchpointStates: [UUID: FriendTouchpointState]`

**Core Algorithm (The "Cycle Algorithm"):**

1. **Anchor Date & Day Calculation:**
   - `anchorDate()` - First day of the app (stored in UserDefaults)
   - `dayNumberSinceAnchor()` - Current absolute day (1-based)
   - `dayInCycle50()` - Position in 50-day super-cycle

2. **Scheduling Logic:**
   - For each circle, friends are assigned to days based on:
     - Cadence: How often to reach out (3, 7, 14, 30, 50 days)
     - Stable order: Sorted by circle priority, then alphabetically by name
     - Formula: `dayInCycle = ((dayNumber - 1) % cadence) + 1`
   - Friend scheduled if their position mod cadence matches today

3. **Rollover Management:**
   - Unfinished contacts from yesterday are re-added to today's queue
   - Tracked in `rolloverQueue: [UUID]`
   - Cleared when marked contacted

4. **State Tracking:**
   - `lastDayNumber` - Last day processed
   - `lastPresented` - Friends shown today
   - Applied daily via `applyRolloverIfDayChanged()`

**Key Methods:**

- **Sync Operations:**
  - `performSync()` - Full sync with Supabase
  - `startRealtimeSync()`, `stopRealtimeSync()` - Real-time polling

- **Data Management:**
  - `loadLocalData()`, `saveLocalData()` - Persistence
  - `buildLocalMetadata()`, `applyMetadata()` - Metadata handling

- **Scheduling:**
  - `refreshToday()` - Recalculate today's due list
  - `scheduledIDsForDay()` - Get friends for a specific day
  - `generateUpcomingDays()` - Preview next 7 days
  - `stableOrder()` - Deterministic friend sorting

- **Public Mutations:**
  - `addFriend()` - Add with auto-numbering

  - `updateFriend()` - Edit name/circle
  - `markContacted()` - Mark as reached out today
  - `renumberFriendsInCircles()` - Reorder numbering
  - `resetCycles()` - Reset to Day 1

- **Touchpoints:**

### **Sync Strategy**
- **Primary:** Supabase with fast polling (2-second interval)
- **Fallback:** CloudKit (disabled, requires paid dev account)
- **Local:** UserDefaults + JSON file
- **Conflict Resolution:** Last-write-wins (modifiedAt timestamp)
- **Data Protection:** Never overwrites local data with empty remote

### **Authentication Flow**
```
User Input (Email/Password)
    ↓
SignInView
    ↓
AuthenticationService
    ├─→ Supabase Auth (email/password/Apple)
    └─→ Optional: Save credentials in Keychain
    ↓
BiometricAuthService (for future logins)
    ├─→ Touch ID / Face ID / Optic ID
    └─→ Auto-fill from Keychain
```

### **The Cycle Algorithm**
```
For each contact:
1. Determine stable order (circle priority, name alphabetically)
2. Assign to days based on cadence: day_in_cycle = (position - 1) % cadence + 1
3. Schedule when: dayInCycle == (absoluteDay - 1) % cadence + 1
4. Roll unfinished contacts forward to next day
5. Display in "Today" list

Example: Contact at position 3 in "Circle of 3" (cadence 3)
- Day 1: shown, marked contacted → complete
- Day 2: not shown
- Day 3: not shown
- Day 4: shown again
```

## **11. CRITICAL LOGIC FLOWS**

**App Launch:**
1. Create FriendViewModel
2. Load local friends from JSON
3. Ensure anchor date exists (create if first launch)
4. Check for saved credentials (Keychain)
5. Check authentication status (Supabase)
6. Refresh today's due list
7. Start real-time sync if authenticated

**Daily Refresh:**
1. Calculate current absolute day
2. Check if day changed (rollover logic)
3. Move unfinished contacts to rollover queue
4. Reset `isContacted` flag for all
5. Recalculate today's schedule
6. Update UI with new due list

**Marking Contacted:**
1. Set `isContacted = true`, update `modifiedAt`
2. Remove from rollover queue
3. Save to local JSON
4. Upload to Supabase async
5. Refresh UI
