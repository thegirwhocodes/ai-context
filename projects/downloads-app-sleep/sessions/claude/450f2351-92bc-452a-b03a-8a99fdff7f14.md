# Deep-research: how top computer blockers work, and what Sleep Well should learn

## 1. The five architectural patterns the market uses

Every serious "focus / bedtime / distraction" blocker sits somewhere on this ladder. Higher tiers survive more attacks.

| # | Pattern | Who uses it | What it survives | What defeats it |
|---|---------|-------------|------------------|-----------------|
| 1 | **Browser extension** | LeechBlock NG, uBlock modes | Casual visits in one browser | Different browser, private mode |
| 2 | **Host file / DNS rewrite** | Freedom (desktop) | Reboot, browser switch | `sudo` edit, VPN, IP-literal URLs |
| 3 | **Local VPN / NetworkExtension** | Freedom (iOS/Android) | Any app that uses standard networking | Disabling the VPN profile |
| 4 | **User-space app that watches processes & covers screens** | Focus, FocusMe, Cold Turkey (unlocked), **Sleep Well today** | Casual use | Force Quit, delete app, log out, Safe Mode |
| 5 | **Privileged LaunchDaemon + pf firewall + tamper checks** | SelfControl, Cold Turkey (locked/Frozen), FocusMe (Enforced Mode) | Force Quit, app deletion, reboot, `rm -rf`, most Terminal escapes | `sudo launchctl unload` + delete lock file; macOS Recovery |
| 6 | **Endpoint Security / kernel filter driver** | Enterprise EDR; some parental-control MDM profiles | Everything short of MDM removal | MDM removal, Recovery, reinstall |
| 7 | **MDM / firmware / physical** | Enterprise MDM; Unpluq (BLE tag); **Sleep Well's USB key** | Software attacks | Physical access to the key, MDM admin |

Sleep Well is currently **tier 4 for enforcement + tier 7 for early-release**. That's a genuinely novel combination — nobody else pairs a user-space session cover with a hardware-key release — but the enforcement layer is the weakest link.

## 2. What each headliner actually does under the hood

- **SelfControl** ([source](https://github.com/SelfControlApp/selfcontrol/)) — installs `org.eyebeam.SelfControl` as a `SMJobBless` privileged helper at `/Library/PrivilegedHelperTools/`, drops a LaunchDaemon at `/Library/LaunchDaemons/org.eyebeam.selfcontrold.plist`, writes a `pf` anchor at `/etc/pf.anchors/org.eyebeam` that adds a "drop" rule per domain, and a timer file at `/etc/SelfControl.lock`. Deleting the app or rebooting does nothing. Bypass requires `sudo launchctl unload` **and** removing the lock file **and** flushing the pf anchor.

- **Cold Turkey Blocker / Frozen Turkey** — OS-level (not extension-based). A "locked block" makes the uninstaller itself refuse to advance. Frozen Turkey locks/logs off/shuts down at scheduled times. Their own docs say Safe Mode is normally required to bypass — same admission Sleep Well makes.

- **Freedom** — hosts-file modification on Mac/Win + app-termination watcher; a "Limited VPN" (Network Extension, no remote server) on iOS. Cross-device session sync. Well-documented iOS bypass: delete & reinstall the app.

- **FocusMe** — process watcher with an "Enforced Mode" that cannot be stopped, layered with typed random-character challenges and stop delays. Same tier-4 pattern as Sleep Well, but adds friction gates rather than a hard contract.

- **Opal / Jomo / One Sec (iOS)** — thin wrappers around `FamilyControls` + `ManagedSettingsStore` + `DeviceActivity`. All bypassable by toggling Screen Time off, because that toggle isn't behind the Screen Time passcode. Industry-wide flaw, not their fault.

- **Unpluq** — Bluetooth keychain tag; closest analog to Sleep Well's USB key, but BLE is spoofable / relayable and the tag is a consumer hardware SKU. Sleep Well's "any USB stick + random secret + Keychain fingerprint + constant-time compare + reject-non-external-volume" is architecturally stronger than Unpluq's tag.

## 3. Where Sleep Well is already best-in-class

1. **Physical-key release, done properly.** Random 256-bit secret on the drive, only SHA-256 fingerprint in Keychain, constant-time compare, rejects internal + network volumes. Nobody in the consumer market does this better; Unpluq's BLE tag is weaker.
2. **Latched original wake time.** Kills the "edit the schedule to shorten tonight" bypass every schedule-based blocker in the market suffers from.
3. **Persisted night latch across relaunch.** Kills the "quit and reopen" bypass — SelfControl gets this via LaunchDaemon; you get it via UserDefaults + latch semantics.
4. **No on-screen escape, no challenge, no timed friction.** Cleaner threat model than Cold Turkey/FocusMe, which are all defeatable at 3am by a determined half-asleep user.
5. **iCloud KVS as unlock channel** rather than a backend service. No server to be offline, no account leakage risk.
6. **Fail-closed** on iCloud non-delivery, on missing key, on relaunch — explicitly designed and documented.

## 4. Concrete architectural gaps, ranked

### Tier 1 — closes actual bypasses, worth doing

**A. Add a privileged LaunchDaemon (SMAppService in macOS 13+, or SMJobBless).** Sleep Well is currently a pure foreground AppKit app. Every serious tamper-resistant blocker moves the *enforcement* into a root daemon and keeps the UI as a mere client. Concrete wins:
- Force Quit / Cmd-Opt-Esc on `Sleep Well.app` doesn't end the night — daemon relaunches it.
- Deleting `/Applications/Sleep Well.app` mid-day doesn't disable tonight — the daemon at `/Library/LaunchDaemons/` still fires.
- The night latch lives in a root-owned file (like SelfControl's `/etc/SelfControl.lock`), so a user with only their own login can't rewrite it via `defaults write`.

**B. Layer `pf` firewall rules during the latched night.** Even with perfect window coverage, if a user finds any Space/keyboard escape (there's always something on macOS), the underlying browser is still online. SelfControl's approach — a `pf` anchor with drop rules for the user's own distraction domains — makes the escape useless because the network is dead. This is *additive* to the current window lock, not a replacement, and preserves the "no on-screen escape" contract.

**C. Confirm iOS is using `ManagedSettingsStore.shared.shield.applications`, not just presenting UI.** From the docs it looks like it does (shields clear/restore on heartbeat), but worth auditing that the shield config is actually installed on iOS during the night and not just the app-side UI. Everyone in the iOS blocker market bottoms out at Apple's Screen Time passcode; you can't do better than that on iOS, but you should be at that ceiling.

### Tier 2 — meaningful hardening

**D. `NSApplication.presentationOptions` audit.** Verify the lock windows set `.disableForceQuit`, `.disableProcessSwitching`, `.hideMenuBar`, `.hideDock`, `.disableSessionTermination`, `.disableAppleMenu`. Any missing option is an escape.

**E. Single-key issuance.** `PhysicalKeyManager.createKey()` should refuse to overwrite an existing fingerprint in Keychain without a "revoke" flow that itself requires the current key. Otherwise a user can just insert a fresh USB stick, click "Create USB Key" again, and mint a spare — trivially defeating the "give it to a friend" model.

**F. iCloud unlock as a one-shot with a monotonic counter.** Right now `activeUnlockUntil` looks like a level-triggered value. If the daemon on Mac writes it during a night, and then the user re-locks (removes USB) and later removes it again, does iOS see two separate releases or does the stale value hang around? Add a nonce/generation counter so each release is single-use per night.

### Tier 3 — polish, not urgent

**G. Endpoint Security `ES_EVENT_TYPE_AUTH_EXEC` deny** for a small user-defined block-list of apps during the night. More surgical than a full session lock. Needs Apple's ES entitlement (non-trivial approval), so this is a "future work" item, not a v1.

**H. In-app "hardness dashboard"** showing: daemon installed ✓, pf anchor loaded ✓, iOS shields registered ✓, key issued ✓, launch-at-login ✓. Removes surprise if any layer regressed.

**I. Honest Recovery-Mode disclosure in the UI**, not just in `ARCHITECTURE_AND_PLAN.md`. Users who read only the app will otherwise overestimate the guarantee.

### Explicitly do NOT copy

- Cold Turkey's typed challenges, FocusMe's stop delays, Freedom's remote unlock code — all social-engineerable at 3am and would violate Sleep Well's "no on-screen escape" contract.
- Bluetooth-tag keys (Unpluq style) — architecturally weaker than the current USB key.
- Backend account approval — introduces a service dependency you've deliberately avoided.

## 5. Bottom line

Sleep Well's **product contract** (no software escape, physical-key-only, latched night, fail-closed) is architecturally sharper than any of the top 10 blockers I looked at. Its **enforcement mechanism** is the market's tier 4 (foreground AppKit) when the contract is asking for tier 5 (privileged daemon + pf) at minimum. The single highest-leverage change is **A + B together**: move the night latch and enforcement into a signed LaunchDaemon and add a pf anchor during locked hours. That closes the two bypasses that don't require Recovery Mode (Force Quit / delete-app, and the "escape the window and browse anyway" case) and brings Sleep Well up to SelfControl-class enforcement while keeping its uniquely clean early-release model.

## What Sleep Well already matches or beats Cold Turkey on

- **Session cover** — `presentationOptions` in [ShutdownAppApp.swift:146](ShutdownApp/ShutdownAppApp.swift:146) already sets `disableForceQuit`, `disableProcessSwitching`, `disableSessionTermination`, `disableHideApplication`, `hideDock`, `hideMenuBar`, `disableAppleMenu`. Cold Turkey's "Frozen Turkey" mode does the same thing.
- **Hard contract** — no typed-code, no "wait 30 seconds" delay, no reasonable-adult challenge. Cold Turkey has all of those, all defeatable at 3am. Yours doesn't.
- **Latched wake time** — [ShutdownManager.swift:276](ShutdownApp/ShutdownManager.swift:276) writes the original wake date and refuses to shorten it. Cold Turkey allows extending a session but the wake-side is weaker.
- **Physical USB key** — cryptographic, constant-time compared, external-volume-only, fingerprint-in-Keychain. Nobody in the market does this properly. Cold Turkey has nothing equivalent.

## Where you're short of Cold Turkey — ranked

**1. The enforcer isn't actually running.** `SleepWellEnforcer/main.swift` is scaffolded on the current branch but has two problems:
   - The Xcode target doesn't exist (only 7 targets in `project.pbxproj`, no enforcer).
   - It reads key `activeMacNightLockUntil` from the App Group, but `ShutdownManager` writes `SleepWell.activeNightLockUntil` to standard `UserDefaults`. Even if the target existed, it wouldn't see the latch.

   This is what closes Cold Turkey's "you can't kill the app" property. **HIGH value, MEDIUM effort.** ~150 lines of Swift + one new Xcode target + one App Group write.

**2. No network-level blocking during the lock.** If any window-escape ever happens (external display cornercase, macOS bug, accessibility trick), the browser underneath still works. Cold Turkey's locked block adds host-file rewrites; SelfControl adds `pf` firewall rules. **MEDIUM value, HIGH effort** — needs a signed privileged helper (root, `SMJobBless`/`SMAppService`).

**3. No uninstall protection during the active night.** Cold Turkey's locked block makes the uninstaller fail. Sleep Well can be dragged to Trash mid-day and the enforcer relaunch loop stops (nothing to relaunch). Fully closing this needs the Endpoint Security entitlement from Apple — **weeks-of-approval effort**.

**4. Not signed for distribution.** README says "signing/device installation remains an Apple-account deployment step." Without a Developer ID Application cert, `SMAppService.agent(plistName:)` won't register the enforcer at all, so #1 above stays a no-op.

## My recommendation

For "Cold Turkey Frozen mode, for the whole computer" you don't need all three tiers I proposed earlier. You need:

- **Finish the enforcer** (fixes bug #1, closes the biggest bypass).
- **Sign the app** (unblocks the enforcer and every future tamper-resistance layer).
- Small hardening: single-key issuance (bug in `PhysicalKeyManager.createKey` — user can mint spare keys), unlock nonce so a synced release isn't replayable, hardness-dashboard in Settings, Recovery-Mode disclosure.

Skip the pf firewall and Endpoint Security work until after signed distribution is running, because both depend on it and both are big lifts. Ship the enforcer first; those two are v2.
