# 1-800-ChatGPT — Complete Research Report

## 1. What It Is

**1-800-ChatGPT** (number: 1-800-242-8478, i.e., 1-800-CHATGPT) is a toll-free phone service launched by OpenAI on December 18, 2024, as part of their "12 Days of OpenAI" campaign. It was built just a few weeks before launch during an internal "hack week." OpenAI frames the mission as accessibility — "make artificial general intelligence beneficial to all of humanity" by reaching people without high-speed internet, without smartphones, without accounts. It works on any phone, including landlines and rotary phones.

There are two channels:
- **Voice call (US and Canada only):** Call 1-800-242-8478, talk directly to ChatGPT over PSTN. Free for 15 minutes per phone number per month (some sources say 30 minutes — there is ambiguity, likely 15 minutes is the confirmed cap). No account required.
- **WhatsApp (global — 150+ countries):** Message or call the same number 1-800-242-8478 on WhatsApp. Also free, with daily message limits. No account required. This channel was deprecated as of January 15, 2026 — no longer available.

## 2. The User Experience

When a user dials:
- A female AI voice answers. The greeting is: **"Hello again, it's ChatGPT, an AI assistant. Our conversation may be reviewed for safety. How can I help you?"**
- No IVR menu, no press-1-for-this, no routing tree. You go straight into open-ended conversation.
- The voice sounds like ChatGPT's Advanced Voice Mode. One CNN journalist called in and got a chocolate chip cookie recipe, a summary of the Civil War, and when asked about feelings, the bot said: "I don't have feelings, but I do find my job pretty interesting."
- When asked if ChatGPT would become profitable, the bot said OpenAI plans to eventually achieve profitability, "though I don't handle any money myself."
- Conversation is open-ended. No rigid intent trees. Full natural dialogue.
- No image uploads, no ChatGPT Search, no custom instructions — more limited than the full app.
- Knowledge cutoff: October 2023 (same as the gpt-realtime model).
- Call quality tips from OpenAI: quieter environments work better, use headphones, iPhone users can enable Voice Isolation mode (Control Center → Mic Mode → Voice Isolation) to reduce background noise.

## 3. The AI Models Used

**Phone calls:** Powered by OpenAI's **Realtime API**, specifically the **`gpt-realtime`** model (GA, not preview). This is a speech-to-speech model — audio goes in, audio comes out, with no separate STT → LLM → TTS pipeline. The model handles everything end-to-end.

**WhatsApp (when it existed):** Used **GPT-4o mini** via the WhatsApp Business API. Text-in, text-out — a separate, lighter pipeline.

### gpt-realtime model specs:
- Context window: 32,000 tokens
- Max output tokens: 4,096
- Knowledge cutoff: October 1, 2023
- Modalities: text in, text out, audio in, audio out (image input supported but not exposed on the phone line)
- Performance: "Highest" performance tier, "Fast" speed designation
- Function calling: supported
- Structured outputs: not supported
- Fine-tuning: not supported
- Pricing (retail API): $4.00/1M text input tokens, $16.00/1M text output, **$32.00/1M audio input tokens**, **$64.00/1M audio output tokens**. Cached input: $0.40/1M.

### There is also a `gpt-realtime-mini` model:
- Lighter, cheaper, lower capability
- Unclear if 1-800-ChatGPT uses this vs full gpt-realtime

## 4. The Technical Stack — How It's Built

### The Core Architecture: Realtime API over SIP

The critical piece: OpenAI's Realtime API natively supports **SIP (Session Initiation Protocol)** as a first-class connection method alongside WebRTC and WebSocket. 1-800-ChatGPT uses this SIP path to receive PSTN calls.

**The full call flow:**

1. User dials 1-800-242-8478 on a regular phone.
2. Call enters the PSTN (public switched telephone network).
3. PSTN routes the call to a **SIP trunking provider** — OpenAI uses a provider like Twilio, Vonage, or Bandwidth. This provider converts the phone call to SIP/IP traffic.
4. The SIP trunk is pointed at OpenAI's SIP endpoint: `sip:$PROJECT_ID@sip.api.openai.com;transport=tls`
5. When a call arrives at that SIP endpoint, OpenAI fires a **`realtime.call.incoming`** webhook event to OpenAI's own webhook handler (internal).
6. The webhook handler calls `POST https://api.openai.com/v1/realtime/calls/$CALL_ID/accept` with the model config (model: "gpt-realtime", instructions, voice, etc.).
7. A WebSocket connection is opened to `wss://api.openai.com/v1/realtime?call_id={callId}` — this is the live session.
8. Audio streams bidirectionally: phone audio in → Realtime API → AI response audio out → back through the SIP trunk → back to the caller's phone.
9. When the call ends (15-minute limit hit, or user hangs up), a `POST .../hangup` call tears down the SIP leg.

**SIP endpoint format:** `sip:[PROJECT_ID]@sip.api.openai.com;transport=tls`  
**OpenAI's allowlisted SIP IP ranges (GeoIP routed to closest region):**
- `13.79.45.80/28` (northeurope)
- `23.98.140.64/28` (southcentralus)
- `40.67.149.176/28` (eastus2)
- `40.83.204.240/28` (westus)

### Audio format in the Realtime API pipeline:
- Format: **PCM16** (16-bit signed linear)
- Sample rate: **24 kHz mono** (16kHz supported but degrades quality)
- Audio transmitted as Base64-encoded chunks over WebSocket
- The Realtime API manages conversation state, phrase endpointing (turn detection via server-side VAD), and bidirectional audio streaming internally

### Turn detection (VAD) config (default for server-side):
```json
{
  "type": "server_vad",
  "silence_duration_ms": 400,
  "threshold": 0.5
}
```
Server-side VAD means OpenAI's servers detect when the user stops speaking — no client-side end-of-utterance detection needed.

### The speech-to-speech pipeline (what makes it different from older voice bots):
Older systems: mic audio → STT (Whisper) → text → LLM → text → TTS → speaker. Three separate models with compounding latency.

Realtime API: `[ audio input ] → [ GPT-4o realtime ] → [ audio output ]` — one model handles it all. No separate Whisper, no separate TTS. This is why latency can reach **sub-200ms** in optimal conditions. The model generates audio tokens directly, not text that gets converted. This gives natural prosody, pacing, and emotional inflection without the "robot reading aloud" artifact.

### Key WebSocket events (in order of a single turn):
1. `session.created` — WebSocket established
2. `session.updated` — session config ack
3. `conversation.created` — once per session
4. `input_audio_buffer.speech_started` — VAD detected user speaking (triggers "listening" state)
5. `input_audio_buffer.speech_stopped` — VAD detected end of user speech
6. `input_audio_buffer.committed` — buffer flushed to server
7. `conversation.item.created` — user item appended
8. `conversation.item.input_audio_transcription.completed` — internal transcript ready (not returned to caller)
9. `response.created` — model started thinking
10. `response.audio.delta` — first audio chunk arrives (model speaking begins, ~200-500ms after response.created)
11. … more `audio.delta` events …
12. `response.audio.done` — TTS stream complete
13. `response.done` — full turn complete
14. `rate_limits.updated`

### Barge-in / interruption:
Supported natively. If the user speaks while the model is mid-response, `input_audio_buffer.speech_started` fires. The system calls `conversation.item.truncate` + `response.cancel`. The model stops mid-word. This is the same mechanism ChatGPT Advanced Voice Mode uses.

### Webhook-based call control API:
- `POST /v1/realtime/calls/{callId}/accept` — accept incoming call, configure model
- `POST /v1/realtime/calls/{callId}/reject` — reject with SIP status code (486 = busy, 603 = decline)
- `POST /v1/realtime/calls/{callId}/refer` — transfer call (target: `tel:+14155550123` or `sip:agent@example.com`)
- `POST /v1/realtime/calls/{callId}/hangup` — hang up

### What config likely powers 1-800-ChatGPT:
Based on the Twilio/OpenAI reference implementation, the accept call body looks like:
```json
{
  "type": "realtime",
  "model": "gpt-realtime",
  "instructions": "[OpenAI's internal system prompt — not public]",
  "audio": {
    "output": { "voice": "alloy" }
  }
}
```
Voice "alloy" is the default in reference implementations. The actual voice OpenAI uses for 1-800-ChatGPT is described as a "female AI voice" in media reports — which corresponds to ChatGPT's default Advanced Voice Mode voice.

### Available voice names in the Realtime API:
"alloy" (confirmed in docs), plus others not fully enumerated publicly.

## 5. No IVR

There is no IVR tree, no press-1-for-English, no skill routing. The experience is exactly Advanced Voice Mode over the phone — open dialogue from the first second. This is architecturally possible because the Realtime API's server-side VAD handles turn detection automatically, and the `gpt-realtime` model handles arbitrary intent in one model rather than routing to specialized skills.

## 6. Infrastructure Notes

- Built in a "few weeks" during an internal hack week — intentionally lightweight/experimental
- OpenAI describes it as "experimental" with "fewer capabilities than the full app"
- No persistent memory across calls — each call is a fresh session (no account = no memory store)
- Data stored linked to phone number, not an account
- Calls not used for model training (OpenAI stated this explicitly)
- OpenAI may review transcripts for safety/abuse prevention

## 7. Strategic Context

- Primary competitive target: **Meta AI on WhatsApp** — by putting ChatGPT directly inside WhatsApp (when that existed), users could switch from Meta AI to ChatGPT without leaving the app
- Secondary goal: accessibility — reaching people in rural/low-connectivity areas, older users on landlines, people without smartphones
- Signals OpenAI's intent to make the Realtime API + SIP stack a platform for voice AI telephony at scale (the same infrastructure is now publicly available for developers)
- The `gpt-realtime` model + SIP docs are public — any developer can build the same thing: buy a Twilio number, point the SIP trunk at `sip:PROJECT_ID@sip.api.openai.com;transport=tls`, write a 100-line Node.js webhook handler, and have a 1-800-ChatGPT clone running in an afternoon
