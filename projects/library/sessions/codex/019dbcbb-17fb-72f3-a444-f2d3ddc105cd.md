## Codex · 2026-04-23T23:48:25.369Z · final_answer

With log utility, the DD problem becomes much cleaner because the planner’s solution has a very simple form.

Start with the planner’s problem:
```text
max  pi ln(c1) + (1-pi) ln(c2)
s.t. pi c1 + (1-pi)c2/R = 1
```

The constraint says the economy has 1 unit of resources at `t=0`. Early consumption `c1` costs 1-for-1, while late consumption `c2` is discounted by `R` because resources invested until period 2 grow by `R`.

The Lagrangian is:
```text
L = pi ln(c1) + (1-pi) ln(c2) + lambda[1 - pi c1 - (1-pi)c2/R]
```

Take FOCs:
```text
dL/dc1 = pi/c1 - lambda pi = 0
dL/dc2 = (1-pi)/c2 - lambda(1-pi)/R = 0
```

From the first one:
```text
1/c1 = lambda
```

From the second:
```text
1/c2 = lambda/R
```

So:
```text
1/c1 = R/c2
=> c2 = R c1
```

That is the key log-utility result: optimal late consumption is `R` times early consumption.

Now plug that into the budget constraint:
```text
pi c1 + (1-pi)(R c1)/R = 1
pi c1 + (1-pi)c1 = 1
c1 = 1
```

So:
```text
c1* = 1
c2* = R
```

That’s why, under log utility, the storage share is exactly:
```text
1 - x* = pi c1* = pi
```
so:
```text
x* = 1 - pi
```

This is the part that matters for your exam problem:
- storage share = `pi`
- long-term investment share = `1-pi`
- promised early payment is `1`
- promised late payment is `R`

So if a bank’s table says storage is `50%`, then `pi = 0.5`.
If storage is `20%`, then `pi = 0.2`.

The intuition is:
- log utility gives just enough desire for smoothing that the planner chooses `c1 = 1`
- then all long-term return shows up in period 2, so `c2 = R`
- that makes the asset allocation very easy: hold exactly enough liquid storage to pay the impatient fraction in period 1
