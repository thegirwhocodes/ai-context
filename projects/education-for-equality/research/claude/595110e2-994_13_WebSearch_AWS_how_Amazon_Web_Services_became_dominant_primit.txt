### The Bezos API Mandate (2002)

In 2002, Jeff Bezos issued what is now known as the API mandate: The new direction at Amazon would be that all capabilities would have to be designed and exposed as APIs. The mandate stated: "All teams will henceforth expose their data and functionality through service interfaces. Teams must communicate with each other through these interfaces."

### Building Blocks as Primitives

Bezos recognized that one day in the future, just as apps proliferate on smartphone platforms, developer-focused services with public APIs could enable businesses to be composed from building blocks provided by specialized vendors. This is the cloud model that AWS came to dominate.

All service interfaces, without exception, must be designed from the ground up to be externalizable. That is to say, the team must plan and design to be able to expose the interface to developers in the outside world.

### Path to AWS Dominance

The blueprint for AWS originated directly from over a decade of Amazon teams building interfaces specifically envisioned for external developer integration based on the mandate. When the public cloud business launched, developers found services resembling internal Amazon APIs but now accessible over the internet.

Those APIs served as the foundation for Amazon Web Services (AWS), Fulfillment By Amazon (FBA), and Amazon Alexa.

### Network Effects and Scale

A good part of API value is created via the network effect: The more capabilities are available as digital building blocks, the more fertile this API landscape becomes for valuable things to be built on top of it. This means that populating the API landscape is an important precondition for API economies of scale to work, and with the API mandate in place, Amazon made sure that the richness of the API landscape is a top priority for the organization.
