Depends what "working" you're capturing — screen or a desk camera? Quick rec either way:

**5 min → 2 sec (150×) is too fast for work capture** — typing/mouse movement becomes an unreadable blur. Good for a hype cut, bad if anyone should *see* what you did.

Better ratios:

| What you want | Ratio | Interval (at 30fps out) |
|---|---|---|
| Readable work timelapse (recommended) | 5 min → 15–30 sec (10–20×) | 1 frame every 0.3–0.7 sec |
| Punchy social clip | 5 min → 5 sec (60×) | 1 frame every 2 sec |
| Extreme hype cut | 5 min → 2 sec (150×) | 1 frame every 5 sec |

**Rule of thumb:** 1 frame every **1–2 seconds** is the sweet spot for capturing coding/writing — fast enough to feel like a timelapse, slow enough to read.

- **iPhone default Timelapse** — auto-adjusts, ends up ~30 sec regardless of length. Fine for casual.

## What HTTP 404 actually means here

`404` from Google's API is literally "that model name doesn't exist for you." The full error was:

## Why "no longer available to new users"

Google Cloud handles Gemini model lifecycles in a way that trips this up all the time:

- **Preview/experimental models get released**, teams start using them.
- **When a successor ships, Google closes off access to the old name for any project that wasn't already calling it.** Existing users get "grandfathered" — you can keep calling `gemini-2.5-pro` if you were already doing so before the cutoff.
- **Your project is new** (you just enabled billing today) → it wasn't calling `gemini-2.5-pro` before the cutoff → 404. Anyone building fresh right now sees the same wall.

The successor model has a different name (something like `gemini-2.5-pro-preview-…` or a newer numbered version), and there are always-available older ones like `gemini-1.5-pro-latest`.
