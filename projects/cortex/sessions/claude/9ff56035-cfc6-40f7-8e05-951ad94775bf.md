Found it. Here's the debug summary:

**Root cause: all six `META_*` env vars on Vercel production were created as empty strings.** The code throws "META_APP_ID is not configured" the moment you hit Connect, so you get bounced back with `?error=instagram_oauth_not_configured`. `.env.local` had no META vars at all, so local was equally broken.

**What I fixed** (set on Vercel production + added to [.env.local](cortex-web/.env.local)):
- `META_APP_SECRET` ← from `meta-app-secret`
- `META_OAUTH_STATE_SECRET` ← from `meta-oauth-state-secret`
- `META_INSTAGRAM_APP_SECRET` ← from `Meta Instagram Login Credentials.rtf` (`21d192...`). Note: the file literally named `meta-instagram-app-secret` contains a 64-char value that's byte-identical to `meta-webhook-verify-token.txt` — that's a webhook verify token mispasted into the wrong file, not an app secret (Meta app secrets are always 32 hex chars). Worth double-checking `21d192...` against the dashboard.
- `META_WEBHOOK_VERIFY_TOKEN` ← from `meta-webhook-verify-token` (`1c1b02...`). Make sure the same value is pasted in the Meta dashboard webhook config, since there were two competing candidates.

**Two things I need from you** — these aren't anywhere in the cortex folder:

1. **Meta App ID** — numeric, shown at the top of [developers.facebook.com/apps](https://developers.facebook.com/apps) → your app → App settings → Basic. Goes into `META_APP_ID`.
2. **Instagram App ID** — under the app's Instagram product ("API setup with Instagram Login"). Goes into `META_INSTAGRAM_APP_ID`.

Paste both here and I'll set them and redeploy prod — OAuth can't work until then, everything else is now in place.
