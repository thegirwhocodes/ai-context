## Key Implementation Approaches

### Real-Time Transcriptions Service

Twilio now offers real-time transcriptions that arrive during the call via webhooks in a Node.js application. Deepgram is available as a second provider option for developers for speech-to-text transcription, alongside Google Speech-to-Text.

### TwiML Gather Verb with Speech Recognition

The `<Gather>` verb in TwiML is used to collect input during a call, which could include speech, digits pressed on the keypad, or both. Between March and June 2025, Twilio is updating speech models for Gather speech-to-text with three choices: setting no speechModel, setting a generic speechModel with language, or setting a specific STT provider and speech model.

When speech input is included, Twilio includes SpeechResult and Confidence parameters, where Confidence contains a confidence score between 0.0 and 1.0, with higher scores indicating greater accuracy potential.

### Webhook Implementation

The statusCallbackUrl attribute specifies where Twilio should send transcription events such as transcription-content or transcription-stopped. In a production setting, developers replace pause instructions with actual call logic such as `<Gather>` to collect user input or interactive voice response (IVR) menus.

### Media Streams Alternative

For more advanced transcription pipelines, developers can use the Media Streams API to stream voice call audio to a WebSocket server, which then passes audio to a transcription service like AssemblyAI to get text back live.

### Compliance & Features

Real-Time Transcriptions using webhooks is HIPAA Eligible and PCI-compliant for safeguarding sensitive interactions.
