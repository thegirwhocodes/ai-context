## The Honest Answer to Your Core Question

Sabi connects to telephony via Asterisk/SIP because telephony is built on **open, standardized, regulated protocols**. Social media is fundamentally different -- these are private, proprietary, closed systems. There is no "SIP for Instagram DMs." But there ARE working approaches across a spectrum of risk and reliability.

---

## 7 Areas Researched

### 1. Data Export/Takeout (GDPR/CCPA)

The **cleanest legal path**. Under GDPR Article 20 and CCPA, users have a legal right to their data in machine-readable format.

- **Instagram:** JSON export includes full DM history (`messages.json`), comments, likes, contacts. Manual request, takes up to 48 hours.
- **Facebook:** JSON export organized as `/Inbox/<chat>/message_1.json` with sender, content, timestamps, reactions.
- **WhatsApp:** Per-chat text export or full account data request (takes ~3 days). Better to access local backups.
- **GroupMe:** Has an "Export My Data" button PLUS a **fully open developer API** with personal access tokens at dev.groupme.com. This is the easiest win.
- **iMessage:** No export tool. Only local database access (see below).

**Cortex strategy:** Build parsers for each format. User manually exports + uploads. Legally bulletproof.

### 2. Browser Automation / Scraping

PhantomBuster, Bardeen, and Clay all carefully **avoid private messages** -- they only scrape public data. Key legal design: "the user is performing the action, we're just a tool."

For Cortex, the **browser extension approach** is strongest: user installs a Chrome extension, extension reads DMs from the page within the user's own browser session, sends data to Cortex. Avoids headless browser detection. This is how Bardeen works.

Playwright/Puppeteer work technically but face bot detection (Cloudflare, DataDome), frequent DOM changes, and rate limiting.

### 3. Protocol-Level Access

**Matrix bridges (mautrix)** are the closest analog to Sabi's Asterisk/SIP approach. Tulir Asokan's bridges reverse-engineer platform protocols and act as "puppets" logging in as the user:

- **mautrix-whatsapp** -- uses whatsmeow (Go library that reverse-engineers WhatsApp's WebSocket protocol). Active and maintained.
- **mautrix-meta** -- bridges Facebook Messenger AND Instagram DMs. v26.02 released Feb 2026. The most important tool for Cortex.
- **Slidge** -- Python XMPP bridges for WhatsApp, Signal, Telegram, Discord, and 5 other platforms. WhatsApp gateway updated Jan 2026.

**whatsmeow** (github.com/tulir/whatsmeow) is the foundation library -- talks directly to WhatsApp's WebSocket servers, no browser needed. This is as close to "protocol-level access" as exists for WhatsApp.

### 4. Local Device Access

**iMessage on Mac** is the most reliable non-API approach:
- SQLite database at `~/Library/Messages/chat.db`
- Tables: `message`, `handle`, `chat`, `attachment` plus join tables
- Requires Full Disk Access permission
- macOS Ventura+ encodes messages as hex blobs in `attributedBody` (decodable)
- Tools: imessage_reader (Python), pymessage-lite, or direct SQL

**How Beeper accessed iMessage:** Mac relay (reads chat.db and forwards) OR reverse-engineered Apple's protocol (Apple blocked this within days). Beeper no longer supports iMessage. Nothing Chats was a security disaster (unencrypted messages on Firebase).

**WhatsApp local backups:** Android stores encrypted SQLite (`msgstore.db.crypt15`) on SD card. WhatsApp-Chat-Exporter can decrypt and export to JSON. iOS has `ChatStorage.sqlite` accessible from iTunes backups.

### 5. Open Source Tools/Libraries

**Tier 1 (actively maintained, production-quality):**
- `whatsapp-web.js` -- Node.js, updated March 2026
- `whatsmeow` -- Go, direct protocol access
- `instagrapi` -- Python Instagram API, supports DMs (WARNING: devs say "more suited for testing/research," account bans common)
- `mautrix-meta` -- Go, FB Messenger + Instagram bridge

**Tier 2 (working but riskier):**
- `instagram-private-api` -- Node.js/TS, npm v1.46.1 (last published ~2 years ago, still used)
- `slidge-whatsapp` -- XMPP gateway, updated Jan 2026
- `WhatsApp-Chat-Exporter` -- parses local backup files to JSON

### 6. Legal/ToS Considerations

- **Reading your own data exports = legal right** (GDPR/CCPA)
- **Reading your own iMessage/WhatsApp from your own device = your property**
- **Using unofficial APIs on your own account = ToS violation (civil, not criminal), risk of account ban**
- **Scraping public data = likely legal (hiQ v. LinkedIn), but hiQ still settled for $500K**
- **Reverse-engineering for interoperability = legal in most jurisdictions (DMCA exemptions)**

**Cortex's best legal position:** Data exports (bulletproof) > local device access (bulletproof) > user-initiated browser extension (strong) > self-hosted bridges (moderate) > server-side scraping (weakest)

### 7. The Telephony Analogy

| Closest to SIP/Asterisk | Most Walled Garden |
|---|---|
| Email (SMTP/IMAP) | iMessage |
| GroupMe (has real API) | Instagram |
| Telegram (Bot API + MTProto) | Facebook Messenger |
| Matrix (open federated protocol) | WhatsApp (reverse-engineered only) |
