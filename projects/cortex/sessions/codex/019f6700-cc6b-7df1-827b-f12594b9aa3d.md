
Commit only redacted recovery artifacts:

- User messages and visible agent responses
- Final subagent reports
- Curated memory and research
- Generated indexes
- Recovery instructions and synchronization tooling

Never commit raw JSONL, SQLite databases, tool outputs, attachments, shell snapshots, configuration, authentication files, or secrets.

### How synchronization should work

1. `SessionStart` pulls the private repository and injects a small `RECOVERY.md`.
2. `UserPromptSubmit` exports the exact current transcript using `session_id` and `transcript_path`.
3. `PostCompact` points directly to that session’s exported file—not whichever session is newest.
4. `Stop` requests a background synchronization.
5. A locked launchd job batches commits every 15–30 minutes, rebases, and retries push conflicts.
6. A local redactor and secret scanner must pass before anything is staged.
7. GitHub Actions provides a second check for secrets, oversized files, broken indexes, and invalid structure.

Codex now officially supports these lifecycle hooks and supplies exact `session_id`, `cwd`, and `transcript_path` fields, so Claude and Codex can share one reliable exporter architecture. [Codex hooks documentation](https://learn.chatgpt.com/docs/hooks)

1. Create `cortex-knowledge` as a private repository.
2. Build and test the redaction/verification gate.
3. Import the 13 Claude transcripts, 17 top-level Codex tasks, memory, research, and useful subagent finals.
4. Install Claude and Codex hooks using exact session identifiers.
5. Make the GitHub-backed `AGENTS.md`, `CLAUDE.md`, and memory files canonical.
6. Test recovery from a fresh temporary clone.
7. Cut over after confirming offline fallback, concurrent sessions, compaction, and secret blocking.
8. Keep the existing OneDrive backup temporarily; retire or narrow it only after every project has equivalent GitHub coverage.

I recommend doing this as a Cortex pilot first, then upgrading `e4e-knowledge` and the other projects to the same shared tooling. No files or repositories were changed during this audit.
