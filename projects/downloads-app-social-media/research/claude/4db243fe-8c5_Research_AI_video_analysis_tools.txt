## 1. GOOGLE GEMINI VIDEO UNDERSTANDING API

**What it does:** The single most capable tool for direct video understanding. Gemini processes video natively -- you upload the video file directly and it analyzes both the visual frames AND the audio track simultaneously. It samples at 1 FPS by default (customizable), processes audio at 1Kbps single channel, and can handle videos up to 1 hour (1M context) or 3 hours at low resolution (or 2 hours with 2M context models). It performs speaker identification/diarization with second-level timestamps, facial expression and emotion detection, scene description, action detection, object tracking, and can connect all of this to a precise timeline.

**Gemini 2.5 Pro specifically:** State-of-the-art on video understanding benchmarks, surpassing GPT-4.1. First natively multimodal model that uses audio-visual information seamlessly with code. Can generate transcripts with speaker diarization and second-level timestamps.

**Gemini 3 (Preview):** Introduces `media_resolution` parameter for granular control over vision processing -- higher resolution reads fine text and small details but costs more tokens.

**API availability:** Fully available via Google AI Studio (Gemini Developer API) and Vertex AI. Upload via the File API for videos > 20MB or > 1 minute. Files expire after 48 hours.

**Token math for video:**
- Default resolution: ~258 tokens/frame, ~300 tokens/second of video
- Low resolution: ~66 tokens/frame, ~100 tokens/second of video
- A 10-minute video at default = ~180,000 tokens input

**Pricing (per 1M tokens, input/output):**
- Gemini 2.0 Flash: $0.10 / $0.40
- Gemini 2.5 Flash: $0.30 / $2.50
- Gemini 3 Flash Preview: $0.50 / $3.00
- Gemini 2.5 Pro: $1.25 / $10.00
- Gemini 3 Pro Preview: $2.00 / $12.00
- Batch API: 50% discount on all models
- Context caching: up to 90% savings

**Cost example:** A 10-minute video (~180K tokens) with Gemini 2.5 Flash = ~$0.054 input + output cost. With 2.5 Pro = ~$0.225 input.

**DaVinci Resolve integration:** You would call the Gemini API from a Python script, get structured JSON back (timestamps, scene descriptions, speaker IDs, edit points), then use that data to generate an EDL/XML or drive DaVinci Resolve's scripting API directly. This is the most promising pipeline for frame-level video analysis feeding into Resolve.

## 3. OPENAI GPT-4o / GPT-4.1 VIDEO ANALYSIS

**What it does:** GPT-4o and GPT-4.1-mini can analyze video by processing extracted frames (NOT native video input). You must extract frames yourself (2-4 FPS recommended), send them as images along with a transcript. GPT-4.1-mini's 1M token context window can hold a large number of frames for a full video.

**Key limitation:** No native video processing. No audio analysis in the vision pipeline -- you must transcribe audio separately (e.g., with Whisper) and send as text alongside frames. Frame sampling loses motion dynamics.

**What it's good for:** Scene description, visual content classification, identifying on-screen text, analyzing compositions. Research shows 0.5 FPS sampling with max 30 frames works for classification tasks.

**API availability:** Fully available. Send images as base64 or URLs in the chat completions API.

**Pricing:** Standard GPT-4o/4.1 token pricing. Image tokens vary by resolution (detail: low = 85 tokens, detail: high = up to 1105 tokens per 512x512 tile).

**DaVinci Resolve integration:** Same pattern as Gemini -- extract frames with ffmpeg, send to API, get structured analysis back, generate EDL/timeline data. More manual pipeline setup required than Gemini since you handle frame extraction yourself.

## 9. WHISPERX (Whisper + Forced Alignment)

**What it does:** Extends OpenAI's Whisper with precise word-level timestamps via forced alignment using Wav2Vec2.0 phoneme models. Key capabilities:
- Word-level timestamps with sub-50ms accuracy via CTC-based forced alignment
- Speaker diarization (who is speaking when)
- Batch inference for faster processing
- Word Error Rate < 5%, Diarization Error Rate ~8%
- Multi-language support

**How it works:** Whisper transcribes in parallel, then WhisperX applies Dynamic Time Warping on Wav2Vec2.0 phoneme recognition to produce precise per-word timestamps.

**API availability:** Open source (GitHub: m-bain/whisperX). Run locally or on your own infrastructure. No hosted API -- you self-host.

**DaVinci Resolve integration:** Output word-level timestamps as JSON/SRT. These timestamps are precise enough for word-by-word animated captions. Can be used to generate EDLs marking silence gaps, filler words, or specific spoken phrases. Feed directly into Resolve's scripting API to place subtitle clips on the timeline.

## 10. CRISPERWHISPER (Verbatim Transcription + Filler Detection)

**What it does:** A Whisper variant specifically designed for VERBATIM transcription -- it transcribes every word exactly as spoken, INCLUDING filler words. Key differentiator: it explicitly detects and labels "uh" vs "um" with precise timestamps, and detects pauses.

**Technical approach:** Uses Dynamic Time Warping on Whisper cross-attention scores for word-level timestamps, plus a retokenization process for consistent pause detection. Specialized AttentionLoss feature improves timestamp accuracy.

**Why this matters for your use case:** This is the best tool for detecting edit points in spoken content. It gives you precise timestamps for every "um", "uh", pause, and hesitation -- exactly the data you need to auto-remove dead air and filler words.

**API availability:** Open source (GitHub: nyrahealth/CrisperWhisper). Self-hosted only.

**DaVinci Resolve integration:** Output JSON with word-level timestamps including filler markers. Write a script that converts filler word timestamps into cut points, generates an EDL, and imports into Resolve. Or use Resolve's scripting API to directly place cuts.

Sources:
- [CrisperWhisper GitHub](https://github.com/nyrahealth/CrisperWhisper)
- [CrisperWhisper Paper](https://arxiv.org/abs/2408.16589)

## 11. PYSCENEDETECT

**What it does:** Open-source Python library and CLI for detecting scene boundaries/shot changes in video. Detection methods:
- **detect-adaptive:** Uses HSL colorspace diffs with rolling average, two-pass algorithm. Best for reducing false positives from camera movement.
- **detect-content:** Fast cuts based on frame content changes.
- **detect-threshold:** Fades in/out detection.

**Output formats:**
- CMX 3600 EDL via `save-edl` command (directly compatible with DaVinci Resolve)
- CSV with HH:MM:SS.nnn timestamps
- Can split video into individual scene clips automatically

**API availability:** Open source, pip installable (`pip install scenedetect`). Python library API for programmatic use. CLI for quick analysis.

**DaVinci Resolve integration:** DIRECT -- exports CMX 3600 EDL which Resolve imports natively via File > Import AAF, EDL, XML. Also generates timestamps that can be used with Resolve's Python scripting API.

## 12. FFMPEG SILENCE DETECTION PIPELINE

**What it does:** FFmpeg's built-in `silencedetect` and `silenceremove` audio filters detect and remove silence from video/audio. The `silencedetect` filter outputs timestamps of silence periods, which can be processed by scripts.

**Key tools in the ecosystem:**
- `ffmpeg -af silencedetect=noise=-30dB:d=0.5` -- detects silence below -30dB lasting > 0.5 seconds
- `silenceremove` filter -- removes silence in-stream
- Multiple open-source wrappers: silencecut-ffmpeg, silence-speedup, Remsi

**Limitation:** Requires manual threshold tuning for noise floor. Different environments/microphones need different settings. Not "intelligent" -- purely amplitude-based, doesn't understand speech vs. intentional pauses.

**API availability:** FFmpeg is open source. Rendi (docs.rendi.dev) offers a hosted FFmpeg API with silence detection/removal as a service.

**DaVinci Resolve integration:** ffmpeg outputs silence timestamps as text. Parse with a script, generate EDL with cuts at silence boundaries, import into Resolve. Or use Resolve's scripting API to place cuts directly.

Sources:
- [FFmpeg + Python Silence Trim](https://dev.to/dak425/automatically-trim-silence-from-video-with-ffmpeg-and-python-2kol)

## 13. AUBIO & LIBROSA (Beat/Onset Detection)

**Aubio:** C library (with Python bindings) for extracting musical meaning from audio -- tempo detection, beat tracking, pitch detection, onset detection. Optimized for speed and real-time processing. Limitation: struggles with MP3 format accuracy.

**Librosa:** Python library for music information retrieval. `librosa.beat.beat_track()` provides dynamic programming beat tracking. `librosa.onset.onset_detect()` identifies transient events (note attacks, beat drops). Handles MP3, OGG, FLAC, M4A formats.

**For your use case:** These detect beat drops in music and vocal onsets -- critical for timing zoom punches and caption emphasis to musical hits. Feed beat timestamps into your caption animation system to sync visual emphasis with audio energy.

**API availability:** Both open source. Aubio: pip install aubio. Librosa: pip install librosa.

**DaVinci Resolve integration:** Extract beat/onset timestamps, convert to timeline markers or cut points, feed into Resolve via scripting API or EDL.

Sources:

## RECOMMENDED PIPELINE ARCHITECTURE
