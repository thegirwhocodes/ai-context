## Environment Variables in UserPromptSubmit Hooks

**For `UserPromptSubmit` hooks, you do NOT use `$CWD` or `$PWD` as environment variables.** Instead, you read the `cwd` field directly from the JSON input that Claude Code passes to your hook on stdin.

The `cwd` is available as a JSON field in the hook input:

```json
{
  "session_id": "abc123",
  "transcript_path": "/Users/...",
  "cwd": "/Users/naomiivie/bethel",  // <-- This is how you get the working directory
  "permission_mode": "default",
  "hook_event_name": "UserPromptSubmit",
  "prompt": "Your prompt text here"
}
```

## Corrected Configuration

Here's how to fix your hook to properly access the working directory:

```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.cwd' | xargs -I {} python3 ~/.claude/scripts/session_context_export.py --cwd {} --quiet &"
          }
        ]
      }
    ]
  }
}
```

Or, more readably, create a separate script:

```bash
#!/bin/bash
INPUT=$(cat)
CWD=$(echo "$INPUT" | jq -r '.cwd')
python3 ~/.claude/scripts/session_context_export.py --cwd "$CWD" --quiet &
exit 0
```

## Key Points

1. **Hook input is JSON on stdin** - Claude Code passes event data as JSON to your hook's standard input
2. **Extract `cwd` from JSON** - Use `jq -r '.cwd'` or similar to parse the working directory
3. **No `$CWD` environment variable** - Unlike some other contexts, UserPromptSubmit hooks don't have `$CWD` as a shell environment variable
4. **Matcher format** - Your empty string `"matcher": ""` is correct; it means "fire on every UserPromptSubmit event"
5. **Command hook syntax** - Your structure with `"type": "command"` is the standard way to configure shell command hooks
