`new_string`:
```typescript
  const result = await response.json();

  const text = (result.text || "").trim();

  // No text at all → definitely nothing intelligible.
  if (!text) {
    return { text: "", confidence: 0 };
  }

  // Derive a MEANINGFUL confidence from Whisper's per-segment diagnostics.
  // Groq's whisper-large-v3 verbose_json returns, per segment:
  //   avg_logprob       — avg log-prob of the chosen tokens (≈ -0.1 good … -1.0+ poor)
  //   no_speech_prob    — P(segment is non-speech / silence)
  //   compression_ratio — high (>2.4) signals repetitive hallucinated garbage
  // We combine all three; avg_logprob alone is nearly constant and never
  // catches "silence" or "hallucination" cases, which is what we care about.
  type Segment = {
    avg_logprob?: number;
    no_speech_prob?: number;
    compression_ratio?: number;
  };
  const segments: Segment[] = Array.isArray(result.segments)
    ? result.segments
    : [];

  if (segments.length === 0) {
    // No diagnostics available; we have text, so assume usable but not certain.
    return { text, confidence: 0.6 };
  }

  const n = segments.length;
  const avgLogProb =
    segments.reduce((sum, s) => sum + (s.avg_logprob ?? -0.5), 0) / n;
  const avgNoSpeech =
    segments.reduce((sum, s) => sum + (s.no_speech_prob ?? 0), 0) / n;
  const maxCompression = segments.reduce(
    (max, s) => Math.max(max, s.compression_ratio ?? 0),
    0
  );

  // Map avg_logprob → [0,1]. Whisper's usable range is roughly -1.2 (bad) to
  // -0.1 (great), so anchor the scale there instead of -1.0→0.0.
  // -1.2 → 0.0, -0.1 → 1.0
  const logProbScore = Math.max(0, Math.min(1, (avgLogProb + 1.2) / 1.1));

  let confidence = logProbScore;

  // Penalize segments that are probably silence / breathing / background noise.
  // no_speech_prob > ~0.6 means Whisper itself thinks there was no speech.
  if (avgNoSpeech > 0.6) {
    confidence *= 0.2;
  } else if (avgNoSpeech > 0.4) {
    confidence *= 0.6;
  }

  // Penalize hallucinated repetition (Whisper invents looping text on noise).
  // compression_ratio > 2.4 is the standard Whisper hallucination threshold.
  if (maxCompression > 2.4) {
    confidence *= 0.3;
  }

  confidence = Math.max(0, Math.min(1, confidence));

  return { text, confidence };
}
```

## Reasoning for the formula

- **Three signals, not one.** `avg_logprob` measures how sure the decoder is about the *tokens it chose*, which is high even when those tokens are wrong. `no_speech_prob` is the actual "was there speech?" detector. `compression_ratio` is the actual "did Whisper hallucinate a repeating loop?" detector (the classic Whisper failure on silence/noise). The bug is that the old code used only the one signal that *doesn't* discriminate the cases we care about.
- **Empty text → 0.** Direct and unambiguous.
- **Rescaled log-prob anchor.** `-1.2 → 0, -0.1 → 1` matches Whisper's real-world distribution far better than `-1.0 → 0, 0.0 → 1`, so genuinely bad audio lands low instead of clustering at 0.7–0.9.
- **Multiplicative penalties** so a segment that is *both* low-logprob *and* likely-silence compounds downward into retry territory, while a clean confident segment stays near 1.0.

## Risk note — do NOT over-reject Nigerian-accented speech

This is the real danger. Mitigations baked into the formula:

- **Accent lowers `avg_logprob` modestly, not catastrophically.** Whisper-large-v3 still transcribes Nigerian English/Pidgin with avg_logprob typically in the -0.3 to -0.6 band → `logProbScore` ≈ 0.55–0.82, comfortably above 0.3/0.35. The wide -1.2→-0.1 scale is deliberately forgiving so accent doesn't tip real speech into retry.
- **The hard penalties key off non-linguistic signals** (`no_speech_prob`, `compression_ratio`), which are accent-*independent* — silence is silence regardless of accent, and hallucinated loops are a decoder artifact, not an accent. This is what makes the gate safe: it punishes "no real speech" rather than "unusual pronunciation."
- **Tunable thresholds.** `no_speech_prob > 0.6` and `compression_ratio > 2.4` are the conventional Whisper values. If field testing shows real kids getting asked to repeat too often, loosen by raising those (e.g. no_speech to 0.7) or lowering the route threshold back to 0.25 — do NOT tighten the log-prob scale.
- **Recommendation:** keep the route threshold at **0.3** initially (not 0.35) and watch real call logs before tightening. Log `confidence`, `avgNoSpeech`, and `maxCompression` for a few sessions so you can calibrate against actual Nigerian-accented audio rather than guessing.

One caveat to flag: I could not 100% confirm from Groq's public docs that the **top-level** response always includes a populated `segments` array for `verbose_json` (Groq mirrors OpenAI's schema, which does include it). The code already handles the missing-segments case — Edit 1 keeps a sane fallback (`confidence: 0.6`) so a missing array degrades gracefully instead of falsely triggering retries.
