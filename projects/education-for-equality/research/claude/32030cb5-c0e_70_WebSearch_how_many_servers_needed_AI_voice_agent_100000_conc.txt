## Hardware Requirements

At minimum, you need GPU-accelerated servers (NVIDIA T4 or better) for model inference, 16-32 core CPUs for audio processing, 64GB+ RAM per node, high-bandwidth network connectivity (100+ Mbps per 100 concurrent calls), and storage systems. Memory allocation of 64-128GB RAM per server to handle multiple concurrent sessions and auto-scaling capabilities to dynamically adjust resources based on call volume are essential.

## Handling Per-Server Concurrency

A critical real-world finding: a single server instance could only handle three or four concurrent users when the agent was actively engaged in conversation. Unlike a traditional LLM that processes a request and moves on, these agents had to maintain persistent connections. This means for 100,000 concurrent users, you'd need substantial horizontal scaling with thousands of server instances.

## Database Scaling Challenges

At 10,000 concurrent calls, each call might write to the database 5–20 times (session updates, transcripts, tool results, call summaries), that's 50,000–200,000 writes per second. Most traditional databases can't handle that. Solutions include Redis for session state: Sub-millisecond reads/writes. Message queues (RabbitMQ, Kafka) for decoupled processing. Time-series databases (ClickHouse, TimescaleDB) for analytics and call metadata.

## Managed Platforms vs. Self-Hosting

For such a large scale, many organizations use managed platforms. Some platforms support up to 1 million concurrent calls, eliminating the need to build custom infrastructure from scratch.
