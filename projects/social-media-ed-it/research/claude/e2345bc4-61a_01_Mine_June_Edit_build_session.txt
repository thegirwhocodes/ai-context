### **3. EVERY DESIGN DECISION & REASONING**

**Tech Stack Decisions:**

| Component | Decision | Reasoning |
|-----------|----------|-----------|
| **LLM Brain** | Claude Agent SDK (Anthropic) | Best for agentic loops, filesystem access, subagents, tool orchestration. Opus 4.7 for creative variation generation. Sonnet 4.5 for routine edits. |
| **UI Framework** | Vercel AI SDK (React) | Unmatched for streaming tool calls and SSE in the browser. Used for the frontend; not the agent brain. |
| **Video Analysis** | Gemini 2.5 Flash | Watches full videos natively; can extract timestamps, scene changes, energy. Cost: ~$0.054 per 10-min video. |
| **Audio Transcription** | WhisperX + CrisperWhisper | Word-level timestamps for captions. Detects pauses, filler words. |
| **Rendering Engine** | FFmpeg (primary) + Resolve MCP (power-user opt-in) | FFmpeg is fully headless and scriptable; handles LUTs, captions, speed ramps, audio ducking. Resolve via MCP for users who have it. |
| **Desktop Shell** | Electron | Mac + Windows distribution. Spawns Python backend as a subprocess on a random free port. Projects stored in `~/Movies/Ed.it Projects/`. |
| **Backend Server** | FastAPI + Python | Bundles the agent loop, tool definitions, and MCP connections. Streams SSE to the frontend. No Vercel (10s timeout limit can't support 2–5 minute renders). |
| **Local Storage** | SQLite + FTS5 | Memory system: `user_profile`, `preferences`, `projects`, `events`, `memory_items`. One file, no external DB required. |
| **Memory Architecture** | Hybrid: Symbolic (SQL) + Vector (sqlite-vec + BGE embeddings) + Episodic (transcript logs) | Allows fast explicit recalls ("user prefers Submagic captions") and fuzzy semantic retrieval ("find times the user rejected something like this"). |
| **Naming** | **Ed.it** | Chosen from editor-insider candidates (Offline, Rushes, Splice were finalists). "Edit" verb + ".it" domain. Punchy, memorable, trademark-friendly. |

**Architectural Decisions:**

1. **Local-first, not cloud-first** — despite initial "global settings" preference for Vercel, the fundamental constraint is that video uploads are 10–50× slower over the internet than on localhost. Desktop Electron is the right layer.

2. **Agent loop with 3-variation rendering** — instead of "here's my best guess," always produce Safe (baseline) / Stretch (one dimension pushed) / Wild (different content mode applied). User becomes curator, not critic. Pick signal trains the memory model.

3. **Proactive file watching** — a `launchd` daemon on macOS (or equivalent on Windows) watches `~/Movies/Ed.it Inbox/` and enqueues edits. When Naomi opens the app, it greets: "I noticed you added 23 clips to your Sunday Worship folder — want me to rough-cut the best 2-min highlight?"

4. **No Instagram integration for MVP** — Naomi uploads manually to phone (30s friction). Graph API posting deferred to v2 with her added as a Tester (avoids 1–4 week Meta App Review).

5. **Memory as first-class product layer** — every suggestion cites its reasoning. "A: your usual 2.8s cuts. B: I shortened to 2.2s for energy. C: tried worship pacing on a talking-head clip — risky." Over time, the agent learns her aesthetic from which variations she picks.

6. **No single "virality score"** — show the *features* instead: hook strength (LLM-scored), pacing variance, speaker face %, emotion peaks, caption density. More honest, more useful than a black-box 0–100 number.

**Content & Output Decisions:**

- **Three default content modes:** talking-head, worship, lifestyle. Each mode has its own taste profile (cut length, caption style, LUT, audio ducking %).
- **Cinematic preset LUTs:** 5–8 curated .cube files shipped with the app. Users can pick, or the agent recommends based on mood.
- **Caption styles:** Bold, Minimal, or Submagic-style (word-by-word animated overlays driven by WhisperX timestamps).
- **Auto-music ducking:** configurable DB reduction under vocals, learned per content mode.
- **Speed ramps on key moments:** agent detects emotional peaks and adds subtle slow-motion for emphasis.

**Greeting & Memory Decisions:**

- **Time-aware greetings:** 5–8 pre-written variations per context (first-of-day: "Good morning, Naomi"; returning same-day: "Welcome back. Where were we?"; after-render: "How's the last one feeling?"). Rotated but never repeat within 3.
- **No greeting if last-active <2 hours.** (Feels robotic otherwise.)
- **Memory writes only on durable signals:** "I prefer…", "always…", "never…", or explicit "remember that." Not every turn — target <1 memory per 10 user turns.
- **Implicit learning:** user rejects a suggestion 3× in a row → write `user.dislikes("jump cuts on worship")`. User picks Variation B three times → shift baseline toward B.
- **Visible taste profile:** a "Your Taste" page showing "You tend to: warm grade (94% of edits), 2.8s cuts, Submagic captions, 85% music duck" — editable sliders so Naomi can steer her own profile.

### **6. THE EMOTIONAL / ASPIRATIONAL THROUGHLINE**

**What Naomi is really trying to make:**

At its core, Ed.it is **"the AI video-editing friend"** — a system that:

1. **Understands her as a creator** — learns her aesthetic, her values (faith-adjacent, worship content), her preferences over time, and **remembers them**.

2. **Feels alive and proactive** — doesn't wait for commands. Watches her file system. Notices she filmed something. Suggests an edit before she even asks. Greets her by name with contextual awareness.

3. **Democratizes professional editing** — turns a 30-min worship recording or talking-head interview into something that would normally require 2–3 hours of manual editing in 2–5 minutes, fully automatically. Empowers creators who can't afford or don't have time for manual post-production.

4. **Respects local privacy** — doesn't upload videos to cloud storage. Everything happens on her Mac. The only external calls are LLM APIs (Gemini, Claude), which are temporary and immediate.

5. **Is intuitive, not gimmicky** — the "agent" aspect isn't a chatbot with personality. It's just a tool that knows her well enough to make smart editorial choices without second-guessing itself. It's confident but humble ("here are 3 options, which feels like you?").

6. **Eventually scales to others like her** — creators in faith communities, coaches, student influencers, people doing work that matters to them but don't have time for Hollywood-grade post-production.

**For whom:**

Naomi is building this for:
- **Herself first** — solve her own editing pain (worship videos, talking-head content).
- **Her community** — faith creators, churches, worship teams.
- **Scaled ambition:** eventually, any creator who wants professional-quality output without the professional-grade time commitment.

**Emotional resonance:**

There's a thread of **respect for the creator's intent** running through all her choices:
- 3 variations instead of 1 (she gets to choose, not the AI)
- Visible reasoning ("why I suggested this cut")
- Editable taste profile ("no, I actually prefer slower cuts")
- Local-first (her content, her hardware, her control)
- No dark patterns (never push notifications, no FOMO, no engagement metrics)

It's close to the values in products like Granola (ambient, not interrupting) and Rewind (capture everything locally, search later) — but for the creative domain. Ed.it should feel like a collaborator, not a manager.
