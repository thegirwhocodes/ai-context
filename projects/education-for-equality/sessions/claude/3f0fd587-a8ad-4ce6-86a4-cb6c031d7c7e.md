## What's adaptable from Sabi

1. **Pre-generated thinking cues** ([main.py:81-87, 102-110](/Users/naomiivie/Education for Equality/sabi-server/main.py)). Sabi pre-renders 5 stock audio files at startup ("Hmm...", "Let me see...", "Okay...") and plays a random one IMMEDIATELY when the user finishes speaking, while RAG+LLM run in the background. Buys 1–2 seconds of audible "thinking" — the user never hears silence between their last word and the bot's first word. **This single trick makes Sabi feel like ChatGPT despite being slower.** Military-flavored cues for Adjutant: "Checking the regs..." / "One moment, Sergeant..." / "Pulling that up..." / "Stand by..." / "Let me see..."

2. **Async TTS with httpx** ([main.py:62-78](/Users/naomiivie/Education for Equality/sabi-server/main.py)). Sabi calls Chatterbox over HTTP from an async coroutine (`async with httpx.AsyncClient`) — never blocks the event loop. Adjutant's current `tts.py` is sync; we'll adapt this for Kokoro-onnx.

3. **Confidence-gated retry** ([main.py:295-298](/Users/naomiivie/Education for Equality/sabi-server/main.py), [voice.py:131-143](/Users/naomiivie/Education for Equality/sabi-server/voice.py)). When STT confidence < 0.5, Sabi plays *"I didn't quite hear that — can you say it again?"* instead of feeding garbage to the LLM. Adjutant currently passes whatever Whisper returns straight in. Easy win.

4. **Confirmed:** Sabi already uses Naomi's voice clone via Chatterbox ([chatterbox-tts/server.py](/Users/naomiivie/Education for Equality/sabi-server/chatterbox-tts/server.py)) — but it lives on `api.eduforequality.org:8001`. Online-only. We can't use it offline at the demo. Kokoro stays our local primary; if you have time post-hackathon, train/host a Naomi-voice Chatterbox locally on the M2 (slow but offline).

What Sabi **doesn't** have that we still need to build: streaming STT, streaming LLM, streaming TTS, VAD-gated continuous listening, AudioWorklet, barge-in. Sabi is telephony-paced (Africa's Talking `<Record>` blocks for full utterance). The Adjutant browser flow goes further.

# The walk-through: voice → 290 boxes filled

Let me trace it for **SGT Chen's leave request** end to end. The DA-31 has ~86 fields and DA-4856 has ~290. Most of them stay empty on any given day. Adjutant only fills the ones the soldier's words actually contain.

## Step 1 — Voice to text

She says into the mic:
> *"I'm Sergeant Chen at Fort Bragg. I need to file ten days of ordinary leave starting June 3 to visit family in Atlanta. Emergency contact is Maria Chen at 919-555-0144."*

Browser captures audio → server → Whisper transcribes → we have a string.

## Step 2 — RAG: pull the regulation that governs this form

Server runs a similarity search over the FAISS index of Army Regulations. For "leave" + "ten days" the top hits are AR 600-8-10 paragraph 4-3 and section 3-1. These chunks aren't used to fill the form — they're used to **constrain** the LLM in step 3 and to populate the citation panel in the UI.

## Step 3 — Pick the form(s)

A regex-based intent classifier (`_infer_forms` in [server.py](/Users/naomiivie/adjutant/adjutant/server.py)) reads the transcript:
- "ten days of ordinary leave" → matches the leave pattern → DA-31
- (If she'd said "JRTC" or "Fort Polk" → DD-1351-2)
- (If she'd said "counsel Garcia" → DA-4856)

One sentence can trigger multiple forms in parallel. For her query: just DA-31.

## Step 4 — The LLM does the actual extraction

This is the magic step. We hand the LLM:
1. Her transcript
2. The DA-31 schema — a list of every field name we care about with a one-line description:
   ```
   name              "Soldier full name (Last, First MI)"
   ssn               "DoD ID / SSN last 4"
   rank              "Pay grade (e.g., E-5)"
   unit              "Unit and station"
   leave_type        "Ordinary | Emergency | Convalescent | PTDY | Permissive | Terminal"
   start_date        "First day of leave (YYYY-MM-DD)"
   end_date          "Last day of leave (YYYY-MM-DD)"
   days_requested    "Total leave days"
   leave_address     "Address while on leave"
   leave_phone       "Phone number while on leave"
   emergency_contact "POC during leave (name + relation)"
   ```
3. Today's date as an anchor for "starting June 3"

The LLM (`llama3.2:3b` running locally via Ollama) returns one JSON object:
```json
{
  "name": "Chen",
  "rank": "E-5",
  "unit": "Fort Bragg",
  "leave_type": "Ordinary",
  "start_date": "2026-06-03",
  "end_date": "2026-06-12",
  "days_requested": 10,
  "leave_address": "Atlanta",
  "emergency_contact": "Maria Chen at 919-555-0144",
  "ssn": null,
  "leave_phone": null
}
```

Note the LLM **left fields null** when the soldier didn't say them. SGT Chen never said her SSN, so `ssn = null`. That's deliberate. Hallucinating a fake SSN would be worse than leaving it blank.

A post-processor in `_correct_leave_type` then double-checks the leave type — the word "emergency" only counted in the *emergency contact* phrase, not as the leave type, so we override to "Ordinary."

## Step 5 — Translate semantic names → real form field names

The LLM thinks in human-readable keys (`name`, `unit`, `start_date`). The real DA-31 PDF has field names like `NAME`, `DEPUNIT`, `DEPDATE`, `ADDRESS` — extracted directly from the Army's own XFA template.

A dict in [pdf_fill.py](/Users/naomiivie/adjutant/adjutant/pdf_fill.py) does the translation:
```python
DA_31_SEMANTIC = {
    "name":              "NAME",
    "ssn":               "SSN",
    "rank":              "POPUP2",
    "unit":              "DEPUNIT",
    "leave_address":     "ADDRESS",
    "start_date":        "DEPDATE",
    "end_date":          "RETDATE",
    "days_requested":    "NUMDAYS",
    ...
}
```

After translation, the data dict is keyed by the Army's own XFA field names. We have **86 possible field names** for DA-31. We only have data for ~9 of them. The other 77 stay empty.

## Step 6 — Walk the layout, draw

`scripts/extract_xfa_template.py` already extracted the Army's XFA template and emitted a JSON file with **every field's coordinates, font, and label** — pulled byte-for-byte from the Army's own form definition. For DA-31 that's 254 items across 2 pages.

The renderer (`_render_xfa_layout` in [pdf_fill.py](/Users/naomiivie/adjutant/adjutant/pdf_fill.py)) iterates them once:

```python
for item in layout["items"]:
    if item["kind"] == "draw":
        # static label like "1. NAME (Last, First, Middle Initial)"
        if item["rule"]:
            draw a horizontal line / rectangle border
        else:
            draw the label text at item["x"], item["y"] with item["font"], item["size"]

    elif item["kind"] == "field":
        # fillable slot
        draw the underline beneath it (so the slot is visible even if empty)
        if data has a value for item["name"]:
            draw the value inside the rect
        # if not, leave it blank — soldier can fill in by hand later
```

So all 86 fields get **drawn** (their underlines, their numbered labels, their borders). Only the 9 with data get **filled**. The rest of the form looks intentionally-blank rather than missing — exactly like a real partially-filled paper DA-31 a soldier hands their S1.

## Step 7 — Output

PDF is written to `filled_forms/DA-31-DEMO-SGTChen.pdf`. Server sends a `PDF_READY` event over the WebSocket. Browser shows the iframe with the filled form. Soldier downloads, prints, signs, hands to S1.

**Total time end-to-end:** ~3–5 seconds from end-of-speech to PDF in the browser, on the M2.

## How DA-4856 with 290 fields works the same way

DA-4856 has more fields but most of them are:
- **Repeating row indices** — Approach checkboxes (Directive / Non-Directive / Combined), Type-of-counseling checkboxes (Performance / Event / etc.), four signature blocks
- **Blank slots** the counselor will fill in by hand later (action items, follow-up dates, reassessment notes)

For Garcia's tardiness counseling, Adjutant fills ~10 fields (Name, Rank, Date, Organization, Counselor, Purpose, Key Points, Plan of Action). The other 280 stay empty until the counselor and counselee sit down and complete them together. ## The reason this scales

Adding a new form is now mechanical:
1. Drop the blank PDF in `forms/`
2. Run `python scripts/extract_xfa_template.py forms/<form>.pdf`
3. Add a 10-line dict mapping semantic names to the form's XFA field names
4. Add a regex pattern to `_infer_forms` so a voice request can trigger it

For a hackathon-scale shop that's ~30 minutes per new form. For a production deployment, it's the same architecture as IPPS-A (which generates fresh layouts via Oracle BI Publisher per form) — you can add the entire DA Pamphlet 25-30 form library this way without touching the rest of the pipeline.

**No, we are not using either.** Both are *cloud* APIs — they need a network round-trip from your laptop. Adjutant's whole demo premise is the wifi cable getting yanked, so a Cerebras or Groq call would die the moment the SCSP judge sees you pull the cable.

|---|---|---|---|
| **whisper.cpp + Core ML encoder** for STT | -2.0s | 1.5h | Low — drop-in via `pywhispercpp` |

| **KV-cache prefix structuring** (already wired in `llm.py` step 2) | -1.5s on repeat turns | 0h, done | — |
