## Research Summary: Voice-Driven Email Triage UX

### 1. **Web Speech API (STT/TTS) Reality**
- **Chrome/Edge**: Full SpeechRecognition support, server-based (requires internet)
- **Safari**: TTS works well (esp. on-device neural voices: Arya, Jenny, Guy—no longer robotic), but SpeechRecognition has significant mobile latency issues
- **Firefox**: No native SpeechRecognition; TTS works but limited
- **Verdict**: Browser SpeechRecognition is fragile across platforms. For production, **offload to OpenAI Realtime API** (handles STT + TTS streaming with <600ms end-to-end latency).

### 2. **Browser TTS Quality**
Apple's on-device neural voices (iOS 18, macOS) are **genuinely non-robotic** and feel calm/natural. However, for truly polished email reading, ElevenLabs or OpenAI TTS produces studio-grade narration that builds trust. Native browser TTS works for MVP but may feel impersonal for calm, hands-free email consumption.

### 3. **Existing Voice Email Products**
- **Superhuman**: Voice recognition for hands-free triage (business plan, $40/user/mo)
- **Spike**: Chat-like interface; no dedicated voice mode yet
- **SaneBox**: Auto-archive + AI reply; no voice
- **Apple Mail + Siri**: Basic voice commands (limited scope)
- **None yet do true "AI reads + user speaks back" in a cohesive loop** — this is a gap Naomi can own.

### 4. **Latency Budget for "Feels Alive"**
- **<300ms**: Natural human conversation rhythm
- **300–600ms**: Acceptable; still feels responsive
- **600–1000ms**: Noticeable pause; tolerable for email context (not call-center calls)
- **>1000ms**: Disrupts flow
- **Recommended target**: <600ms (first-audio from end-of-user-speech) ← OpenAI Realtime API delivers this at scale.

### 5. **Wake-Word vs. Push-to-Talk**
- **Push-to-Talk**: Simplest for MVP (visual tap/hold button), lower privacy concerns, predictable activation
- **Wake-Word**: More hands-free; requires on-device detection (Picovoice/Porcupine) to avoid privacy + latency issues
- **For email triage**: **Push-to-talk is the right choice** — users consciously engage per email, no false activations, feels intentional

---

### **Build Plan Recommendations**
1. **STT/TTS**: Use **OpenAI Realtime API** (WebSocket streaming, <600ms latency, best-in-class voice quality)
2. **UI Pattern**: One-email-at-a-time card → **Push-to-talk button** → user speaks reply intent ("reply casually", "archive", "skip") → AI drafts/acts
3. **Stack**: Next.js 15 + Vercel AI SDK (handles streaming) + OpenAI Realtime client library
4. **Voice Quality**: OpenAI's TTS for email reading (sounds trusted + calm), user STT via Realtime
5. **No wake-word needed** — push-to-talk keeps friction low and intentional

**Key Fit**: OpenAI Realtime API is purpose-built for this. Vercel AI SDK has streaming helpers but doesn't replace Realtime's audio streaming codec. This is your competitive edge vs. Gmail/Superhuman.
