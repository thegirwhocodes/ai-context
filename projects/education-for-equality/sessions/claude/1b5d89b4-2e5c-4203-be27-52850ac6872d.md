**What I found on 136.243.8.51**

   - 12:03:39 from `+2349044218460`
   - 17:17:46 / 17:18:07 / 17:18:24 from `+2348124724459`

   So AT *is* routing the DID to the trunk and Asterisk *is* accepting it. The note in memory saying "there has never been SIP traffic from Africa's Talking" is wrong — I've corrected it.

2. **Why that got missed:** that conclusion came from the CDR. `/etc/asterisk/cdr.conf` leaves `unanswered = no` (the default), and every AT leg so far is a flash ring-and-hangup or an unanswered outbound — none of which writes a CDR row. All 41 CDR rows are Twilio simply because Twilio legs are the only ones ever *answered*.

3. **The actual break — the callback left on the wrong carrier.** Each of those AT flashes triggered:
   ```
   -- Called +2349044218460@twilio
   -- Called +2348124724459@twilio
   ```
   Twilio is a **Trial** account with exactly one verified caller ID (`+18604367048`), so it cannot dial a Nigerian number at all. Those three callers rang in, hung up, and were never rung back. That is the "it didn't work."

4. **Config is right now.** `.env` and the container were both rewritten at 21:16 UTC: `SABI_SIP_PROVIDER=africastalking`, `SABI_CALLER_ID=+2342017001459`. Trunk plumbing is sound — endpoint `africastalking`, identify match `102.223.37.68`, `context=from-at`, alaw; ufw allows 5060/udp and RTP 10000-10100 from that IP; zero auth failures in `messages`.
