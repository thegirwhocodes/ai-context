## Authoritative Answers

**1. Can you run Claude Code from the Claude DESKTOP app pointed at a LOCAL directory?**

**Yes.** The Desktop app has a **Local** execution environment option. Here are the exact steps:

1. Download and install the Claude Desktop app from https://claude.ai/api/desktop/darwin/universal/dmg/latest/redirect (macOS)
2. Launch Claude and sign in
3. Click the **Code** tab at the top
4. Select **Local** from the environment selector
5. Click **Select folder** and choose `/Users/naomiivie/cortex`
6. Choose a model from the dropdown
7. Type your task and send

The Desktop app edits local files directly, runs local dev servers via the integrated terminal, and you view output in your browser (localhost or Vercel URLs).

**Requirements:** Pro/Max/Team/Enterprise Claude subscription. On Windows, Git must be installed; most Macs include it by default.

---

**2. How does the Desktop app (local) differ from claude.ai/code (web)?**

| Aspect | Desktop (Local) | Web (claude.ai/code) |
|---|---|---|
| **Code runs on** | Your Mac | Anthropic cloud VM |
| **Edits local files** | Yes, directly | No — clones repo to cloud VM only |
| **Needs GitHub** | No | Yes (or bundle local repo via CLI) |
| **Uses your local config** | Yes (CLAUDE.md, MCP, hooks, etc.) | No (repo only) |
| **Network access** | Your machine's network | Configurable per environment |
| **Permission modes** | All (Ask, Auto-accept, Plan, Auto) | Accept edits, Plan, Auto only |
| **When to use** | Default for local work; full IDE-like control | For parallel tasks, repos you don't have locally, or async work |

**Key distinction:** Desktop Local = your files stay on your Mac. Web = everything runs in a remote sandbox; you review the PR diff afterward. The web version is better for "fire and forget" tasks; Desktop Local is better when you're steering in real time.

---

**3. Is the Desktop app lighter on RAM than the VS Code extension?**

**The documentation does not specify RAM usage comparisons.** However, the Desktop app is a standalone native application (separate from VS Code), so it should use less RAM than running VS Code + the extension together. The Desktop app shares the same Claude Code engine as all other interfaces, but it doesn't require VS Code to be running.

For your use case (switching from VS Code extension to Desktop), you'd close VS Code entirely and just run the Desktop app—so RAM usage should drop significantly.

---

**4. When switching from VS Code to Desktop, is it a new session or can it resume?**

**Each is a separate session.** VS Code sessions and Desktop sessions are independent; you cannot resume a VS Code conversation in the Desktop app.

However:
- **Session files are shared locally.** Both VS Code and Desktop read/write to `~/.claude/projects/` where all your sessions are stored.
- **You can view and resume old sessions.** In the Desktop app, click the session picker (sidebar) to browse and resume any previous session—including ones started in VS Code or the CLI.
- **CLAUDE.md and memory persist.** Any `CLAUDE.md` file or auto memory you built in VS Code carries over to Desktop sessions in the same project, so Claude starts with the same context and instructions.

So while you can't *continue* a live conversation thread across surfaces, all learned context, instructions, and session history are available to new sessions in the Desktop app.

---

**Bottom line for the user:** Install the Claude Desktop app, select **Local** mode, pick the `/cortex` folder, and start working. RAM should drop compared to VS Code. You lose the ability to continue a live conversation thread, but all project memory and instructions carry forward to Desktop automatically.
